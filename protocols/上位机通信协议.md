# FreqCounterOS 上位机通信协议

本文档描述 FreqCounterOS 固件**当前实际实现**的命令行为。与设计意图存在偏差之处（例如部分命令不返回响应）已如实标注，并在第 6 节汇总。

## 1. 协议概述

### 1.1 通信方式

| 接口 | 状态 |
|------|------|
| TCP Socket | **可用** |
| UART 串口 | 代码存在但未接入，当前不可用（见 5.2） |

### 1.2 TCP 连接参数

| 参数 | 值 |
|------|------|
| IP 地址 | 192.168.1.115（静态，在 `main.c` 中定义） |
| 端口号 | 5025 |
| 连接模式 | 设备为 Server |
| 接收缓冲 | 1500 字节 |

### 1.3 帧格式

命令：

```
[命令字符串]\n
```

- ASCII 明文，必须以 `\n` (0x0A) 结尾
- **区分大小写**，固件逐字符精确匹配，必须全大写
- 带参数的命令，命令头与参数之间必须恰好一个空格

响应：

```
[响应数据]\n
```

**并非所有命令都有响应**。无响应的命令列表见 1.5。

### 1.4 匹配方式说明

固件对命令做的是逐字符比对而非分词解析，因此：

- 多余的前导空格、大小写差异、命令头拼写偏差都会导致命令被静默丢弃
- 无法识别的命令**不返回任何数据、不报错、不断开连接**
- 参数部分用 `atoi()` / `atof()` 解析，非法字符按 0 处理

上位机必须实现超时机制。

### 1.5 有无响应速查

| 有响应 | 无响应 |
|--------|--------|
| `*IDN?` | `*RST` |
| `READ?` | `*OPC?` |
| `MEAS:FREQ?` | `CONF:FREQ <值>` |
| `CONF:FREQ?` | `FREQ:GATE:TIME <值>` |
| `FREQ:GATE:TIME?` | `START:GATE:TIME <值>` |
| `START:GATE:TIME?` | `PPM <值>` |
| `SIG:PREF <值>` | `INIT` |
| `SIG:REFCLOCK <值>` | |
| `SIG:OCXO <值>` | |
| `SIG:STATUS0?` | |
| `SIG:STATUS1?` | |
| `PPM?` | |
| `READ:TIME?` | |

### 1.6 超时建议

| 场景 | 建议超时 |
|------|----------|
| 连接建立 | 5000 ms |
| 查询类命令 | 1000 ms |
| `READ?` / `MEAS:FREQ?` | 闸门时间 + 500 ms |
| `READ:TIME?` | 不建议使用，见 6.2 |

## 2. 系统命令

### 2.1 `*IDN?` — 查询设备信息

```
发送: *IDN?\n
响应: HALLIWAY,FREQ-COUNTER,C1804,1.00-1.00-01-1\n
```

| 字段 | 含义 |
|------|------|
| HALLIWAY | 制造商 |
| FREQ-COUNTER | 设备类型 |
| C1804 | 型号 |
| 1.00-1.00-01-1 | 版本号 |

### 2.2 `*RST` — 设备复位

```
发送: *RST\n
响应: 无
```

固件中该分支为空实现，不执行任何复位动作，也不返回数据。

### 2.3 `*OPC?` — 查询操作完成

```
发送: *OPC?\n
响应: 无
```

同样为空实现。

## 3. 频率测量命令

### 3.1 `READ?` — 读取频率

```
发送: READ?\n
响应: 10000000.12345\n
```

| 字段 | 类型 | 格式 | 单位 |
|------|------|------|------|
| 频率值 | double | `%.5f` | Hz |

执行一次完整测量后返回，阻塞时间约等于当前闸门时间。

**测量模式由 `FREF` 决定**：

```
safe_limit = (基准频率 / 2) × 0.9 = 140 625 000 Hz
FREF >  safe_limit  →  等精度法 + TDC 校正
FREF <= safe_limit  →  时间戳法 + 线性回归（精度更高）
```

因此测量前必须用 `CONF:FREQ` 设定被测信号的大致频率，否则会用错模式。上电默认 `FREF = 1000000`（1 MHz）。

测量失败（时间戳条目少于 3 条）时返回 `0.00000\n`。

### 3.2 `MEAS:FREQ?` — 测量频率

与 `READ?` 完全等价，调用同一函数。

```
发送: MEAS:FREQ?\n
响应: 10000000.12345\n
```

## 4. 配置命令

### 4.1 `CONF:FREQ?` — 查询参考频率

```
发送: CONF:FREQ?\n
响应: 10000000\n
```

返回整数，单位 Hz。

### 4.2 `CONF:FREQ <值>` — 设置参考频率

```
发送: CONF:FREQ 10000000\n
响应: 无
```

| 参数 | 类型 | 单位 | 说明 |
|------|------|------|------|
| 值 | int | Hz | 被测信号的大致频率 |

该值仅用于选择测量模式和自适应 `edge_skip`，不影响测量结果的计算基准（基准来自 312.5 MHz 时钟）。

上位机若需确认设置成功，应随后发送 `CONF:FREQ?` 回读。

### 4.3 `FREQ:GATE:TIME?` — 查询闸门时间

```
发送: FREQ:GATE:TIME?\n
响应: 100.000\n
```

| 字段 | 类型 | 格式 | 单位 |
|------|------|------|------|
| 闸门时间 | double | `%.3f` | **ms** |

### 4.4 `FREQ:GATE:TIME <值>` — 设置闸门时间

```
发送: FREQ:GATE:TIME 1\n
响应: 无
```

| 参数 | 类型 | 单位 |
|------|------|------|
| 值 | double | **秒** |

**注意单位不对称**：设置用秒，查询返回毫秒。发送 `FREQ:GATE:TIME 1` 后，`FREQ:GATE:TIME?` 返回 `1000.000`。

上电默认 100 ms。参数为任意浮点数，不限于特定档位——闸门时长由软件 `usleep` 实现，非硬件定时器分频。常用值：

| 输入（秒） | 闸门（ms） | 适用场景 |
|-----------|-----------|----------|
| 0.001 | 1 | 快速测量 |
| 0.01 | 10 | 中速 |
| 0.1 | 100 | 默认 |
| 1 | 1000 | 高精度 |
| 10 | 10000 | 超高精度 |

时间戳模式下闸门时间会被强制到至少 1 ms。

### 4.5 `START:GATE:TIME?` — 查询启动闸门时间

```
发送: START:GATE:TIME?\n
响应: 0.100\n
```

单位 ms，`%.3f`，上电默认 0.1 ms。

### 4.6 `START:GATE:TIME <值>` — 设置启动闸门时间

```
发送: START:GATE:TIME 0.001\n
响应: 无
```

参数单位为**秒**，内部转换为 ms 存储。仅用于 `INIT` 启动时间测量流程。

## 5. 信号控制命令

### 5.1 输出控制

三条命令格式一致，参数只能是单个字符 `0` 或 `1`，其他值不做任何处理也不响应。

| 命令 | 控制的管脚 | 响应 |
|------|-----------|------|
| `SIG:PREF <0/1>` | CTR_PRIREF (W15) | `1\n` |
| `SIG:REFCLOCK <0/1>` | CTR_REF_CLOCK (V16) | `1\n` |
| `SIG:OCXO <0/1>` | CTR_OCXO (W16) | `1\n` |

```
发送: SIG:PREF 1\n
响应: 1\n
```

响应固定为 `1`，表示命令已受理，不反映实际电平。上电后三者均被初始化为 1。

### 5.2 状态查询

| 命令 | 读取的管脚 | 响应 |
|------|-----------|------|
| `SIG:STATUS0?` | CTR_STATUS0 (W14) | `0\n` 或 `1\n` |
| `SIG:STATUS1?` | CTR_STATUS1 (W13) | `0\n` 或 `1\n` |

```
发送: SIG:STATUS0?\n
响应: 1\n
```

**CTR_STATUS0 有额外含义**：它决定频率运算使用哪个基准值。

| STATUS0 | 基准频率来源 |
|---------|--------------|
| 1 | SD 卡 `FREQ.TXT` 中的校准值 |
| 0 | 理想值 312 500 000 Hz |

## 6. PPM 与启动时间测量

### 6.1 `PPM?` / `PPM <值>`

```
发送: PPM?\n
响应: 100\n

发送: PPM 100\n
响应: 无
```

设置启动时间测量的稳定判据：当测得频率与 `FREF` 的偏差落在 ±PPM 内，认为信号已稳定。上电默认 0。

### 6.2 `INIT` — 启动时间测量

```
发送: INIT\n
响应: 无
```

> **注意：无超时。** `InitStartT()` 在 `while(1)` 中等待启动触发信号 `CTR_START_T` 变为 1，该循环既无超时也无 sleep。
>
> 触发信号读取自 Counter_Sig IP 的 REG2（早期版本误读 Counter IP 的 REG18，该寄存器未连接硬件恒为 0，导致命令必然死锁；此问题已修复）。
>
> 若外部触发始终不到来，连接仍会被无限期占用。上位机应在发送 `INIT` 后自行设置超时，并准备好重连。

设计意图的流程为：等待 CTR_START_T 触发 → 以 `START:GATE:TIME` 为闸门连续测量最多 1000 次 → 首次满足 `|偏差| ≤ PPM` 时记录耗时 `(START_GATE_TIME + 0.02) × 次数` ms。

### 6.3 `READ:TIME?` — 读取启动时间

```
发送: READ:TIME?\n
响应: 120.060\n
```

单位 ms，`%.3f`。

该命令内部是**忙等待**（`while(1)` 轮询 `START_T_END` 标志，无 sleep 无超时）。若未先成功执行 `INIT`，同样会永久阻塞连接。

## 8. 使用示例

### 8.1 Python

```python
import socket

class FreqCounter:
    def __init__(self, ip='192.168.1.115', port=5025, timeout=5.0):
        self.sock = socket.create_connection((ip, port), timeout=timeout)
        self.sock.settimeout(timeout)

    def _send(self, cmd):
        """发送不期待响应的命令"""
        self.sock.sendall((cmd + '\n').encode())

    def _query(self, cmd):
        """发送并读取一行响应"""
        self.sock.sendall((cmd + '\n').encode())
        return self.sock.recv(1024).decode().strip()

    def idn(self):
        return self._query('*IDN?')

    def set_fref(self, hz):
        self._send(f'CONF:FREQ {int(hz)}')
        return int(self._query('CONF:FREQ?'))    # 回读确认

    def set_gate(self, seconds):
        self._send(f'FREQ:GATE:TIME {seconds}')
        return float(self._query('FREQ:GATE:TIME?'))   # 返回 ms

    def measure(self, gate_sec=None):
        if gate_sec:
            self.sock.settimeout(gate_sec + 0.5)
        return float(self._query('READ?'))

    def close(self):
        self.sock.close()


if __name__ == '__main__':
    fc = FreqCounter()
    print('设备:', fc.idn())

    fc.set_fref(10_000_000)          # 10 MHz，走时间戳法
    gate_ms = fc.set_gate(1)         # 1 秒闸门
    print(f'闸门: {gate_ms} ms')

    print(f'频率: {fc.measure(gate_sec=1):.5f} Hz')
    print('STATUS0:', fc._query('SIG:STATUS0?'))

    fc.close()
```

### 8.2 C#

```csharp
using System;
using System.IO;
using System.Net.Sockets;

class FreqCounterClient : IDisposable
{
    private readonly TcpClient client;
    private readonly StreamReader reader;
    private readonly StreamWriter writer;

    public FreqCounterClient(string ip = "192.168.1.115", int port = 5025)
    {
        client = new TcpClient(ip, port);
        var stream = client.GetStream();
        stream.ReadTimeout = 5000;
        reader = new StreamReader(stream);
        writer = new StreamWriter(stream) { AutoFlush = true, NewLine = "\n" };
    }

    /// <summary>发送不期待响应的命令</summary>
    public void Send(string cmd) => writer.WriteLine(cmd);

    /// <summary>发送并读取一行响应</summary>
    public string Query(string cmd)
    {
        writer.WriteLine(cmd);
        return reader.ReadLine()?.Trim();
    }

    public double Measure() => double.Parse(Query("READ?"));

    public void Dispose() => client?.Close();
}

// 用法
using (var fc = new FreqCounterClient())
{
    Console.WriteLine("设备: " + fc.Query("*IDN?"));
    fc.Send("CONF:FREQ 10000000");
    Console.WriteLine("参考频率: " + fc.Query("CONF:FREQ?"));
    Console.WriteLine($"频率: {fc.Measure():F5} Hz");
}
```

## 9. 上位机实现要点

1. **区分「无响应」与「超时」**。参照 1.5 的分类，对无响应命令不要等待读取；需要确认时用对应的查询命令回读。

2. **命令必须全大写、精确拼写**。小写或多余空格会被静默丢弃，表现为「超时」，容易误判为设备故障。

3. **测量前先设 `FREF`**。它决定走时间戳法还是等精度法，设错会显著影响精度。

4. **注意单位换算**。`FREQ:GATE:TIME` 和 `START:GATE:TIME` 设置用秒、查询返回毫秒。

5. **`INIT` / `READ:TIME?` 需自行设超时**。固件侧的等待循环无超时保护，见 6.2。

6. **连接管理**。每个连接由独立 FreeRTOS 任务处理，可建立多个连接，但设备资源有限且命令处理共享全局状态（`FREF`、`GATE_TIME` 等），建议上位机只维持单一连接。发送 `quit` 主动断开。

7. **`READ?` 是阻塞的**，占用时间约等于闸门时间。长闸门（10 秒）时务必放大 socket 超时。

## 11. 常见问题

**Q1: 发送命令后没有响应？**

先对照 1.5 确认该命令是否本来就无响应。若属于有响应类，检查：命令是否全大写、是否以 `\n` 结尾、参数前是否恰好一个空格。

**Q2: 测量结果不准确？**

- `FREF` 是否设置正确（决定测量模式）
- 闸门时间是否过短
- `SIG:STATUS0?` 是否为 1（是否启用了 SD 卡校准值）
- SD 卡 `FREQ.TXT` 中的校准值是否与实际 OCXO 输出一致

**Q3: 返回 `0.00000`？**

时间戳模式下 FIFO 采集到的边沿少于 3 条，通常意味着被测信号缺失、幅度不足或频率远低于预期。

**Q4: 闸门时间只能取固定档位吗？**

不是。闸门由软件延时实现，可设任意值。但精度受 FreeRTOS 调度影响，并非硬件定时。

**Q5: 串口能用吗？**

当前不能，见 README「已知问题」第 4 条。

# FreqCounterOS 上位机通信协议

本文档描述 FreqCounterOS 固件**当前实际实现**的命令行为。与设计意图存在偏差之处（例如部分命令不返回响应）已如实标注，并在第 8 节汇总。

> **v6.4 变更提要**：新增 `SIG:STARTT?` 读触发脚电平。断开夹具 VCC 后应轮询它到 `0`
> 再发 `STARTUP:INIT`，否则电源轨尚未放电到门限以下，测量会被拒（`STARTUP:TIME?` 返回 `-3`）。

> **v6.3 变更提要**：`STARTUP:SPAN <值>` 与 `STARTUP:WIN <值>` 改为**无响应**
> （v6.0~v6.2 曾应答 `1`）。若上位机此前为它们读过响应，**必须去掉那两次读**，否则会反向错位。

> **v6.2 变更提要**：起振测量改为**两段式**。`STARTUP:INIT`（新增，纯写指令、无响应）令下位机开始监测
> `CTR_START_T`，上位机随后合夹具 VCC 触发测量，再用 `STARTUP:TIME?` 取回结果。
> 原先由 `STARTUP:TIME?` 一条命令阻塞完成全过程的用法**已不再适用**：现在单独发 `STARTUP:TIME?`
> 会返回 `-6`。完整流程见 7.9。

> **v6.1 变更提要**：起振测量新增 `STARTUP:WIN`，直接设定时间分辨率（微秒，默认 10 µs），
> 窗口条数由它与跨度推算。第 7 章小节顺延（原 7.3~7.6 变 7.5~7.8）。

> **v6.0 变更提要**：新增第 7 章「起振时间测量」，三条 `STARTUP:*` 命令。
> `PPM` 从「只保存不使用」变成 `STARTUP:TIME?` 的判据。原第 7 章及其后章节顺延重编号
> （速查表 7→8，使用示例 8→9，实现要点 9→10，技术参数 10→11，常见问题 11→12，版本历史 12→13）。
> 已有命令的格式与语义不变，按 v5.1 编写的上位机无需修改。

> **v3.0 变更提要**：固件的命令解析已重构为统一的命令表（`src/scpi/scpi.c`），串口与网口共用同一份实现。
> 由此带来三项对上位机可见的变化：**命令不再区分大小写**、**参数前允许多个空格**、
> 以及文档此前一处拼写错误的更正（`SIG:PREF` → **`SIG:PRIREF`**，详见 5.1）。
> 所有命令的响应格式与语义均未改变，按 v2.1 编写的上位机无需修改即可继续工作。

## 1. 协议概述

### 1.1 通信方式

| 接口 | 状态 |
|------|------|
| TCP Socket | **可用** |
| UART 串口 | 代码存在但未接入，当前不可用（见 12 Q5） |

自 v3.0 起两个接口共用同一命令表，支持的命令、参数与响应完全一致。
串口一旦接入即与网口行为等价，无需另行适配。

### 1.2 TCP 连接参数

| 参数 | 值 |
|------|------|
| IP 地址 | 192.168.1.115（静态默认值，在 `main.c` 中定义；BSP 中 `LWIP_DHCP = 0`） |
| 端口号 | 5025 |
| 连接模式 | 设备为 Server |
| 接收缓冲 | 1500 字节（单条命令最长 1499 字节） |

设备上电时会读取 SD 卡根目录的 `IPCFG.TXT`（`IP=` / `MASK=` / `GW=` 三行），读取成功则用其中的地址，读不到或地址非法则回退到上表的默认值。改地址只需编辑该文件并重新上电，实际生效的地址会在串口调试输出中打印。

### 1.3 帧格式

命令：

```
[命令字符串]\n
```

- ASCII 明文，以 `\n` (0x0A) 结尾；`\r\n` 同样被正确处理
- **不区分大小写**（v3.0 起）。`*IDN?`、`*idn?`、`*Idn?` 等价
- 命令头与参数之间可以是一个或多个空格；允许前导空格

响应：

```
[响应数据]\n
```

**并非所有命令都有响应**。无响应的命令列表见 1.5。

### 1.4 匹配规则

固件按命令表逐条匹配，规则是：命令名之后必须紧跟**行尾或空格**，否则该条不算命中。

由此产生的实际约束：

- **命令名必须完整，包括尾部的问号。** `MEAS:FREQ`（漏掉 `?`）不会被识别，
  因为 `?` 既不是空格也不是行尾。
- 前缀相似的命令不会互相干扰。`CONF:FREQ?` 与 `CONF:FREQ <值>`、
  `FREQ:GATE:TIME?` 与 `FREQ:GATE:TIME <值>` 各自独立。
- 无法识别的命令**不返回任何数据、不报错、不断开连接**。
- 参数部分用 `atoi()` / `atof()` 解析，非法字符按 0 处理。

上位机必须实现超时机制。

> 实现位置：`src/scpi/scpi.c` 的 `g_scpi_cmds[]` 命令表与 `scpi_match()`。
> 新增命令只需在该表增加一行，串口与网口同时生效。

### 1.5 有无响应速查

| 有响应 | 无响应 |
|--------|--------|
| `*IDN?` | `*RST` |

| `CONF:FREQ?` | `FREQ:GATE:TIME <值>` |
| `FREQ:GATE:TIME?` | `PPM <值>` |
| `PPM?` | `STARTUP:SPAN <值>` |
| `SIG:PRIREF <值>` | `STARTUP:WIN <值>` |
| `SIG:REFCLOCK <值>` | `STARTUP:INIT` |
| `SIG:OCXO <值>` | |
| `SIG:STARTT?` | |
| `SIG:STATUS0?` | |
| `SIG:STATUS1?` | |
| `CAL:REF?` | |
| `CAL:REF:PREP` | |

规律：**带 `?` 的查询一律有响应，不带 `?` 的设置一律无响应**，例外只有 `SIG:*` 三条
输出控制与 `CAL:REF:PREP`（它们回 `1` 表示受理，是历史行为）。

### 1.6 超时建议

| 场景 | 建议超时 |
|------|----------|

## 3. 频率测量命令

### 3.1 `READ?` — 读取频率

```
发送: READ?\n
响应: 10000000.12345\n
```

| 字段 | 类型 | 格式 | 单位 |
|------|------|------|------|
| 频率值 | double | `%.5f` | Hz |

执行一次完整测量后返回，阻塞时间约等于当前闸门时间。

**测量算法只有一种**（时间戳法 + 线性回归）。`FREF` 决定的是要不要在硬件里先把被测信号
四分频：

```
safe_limit = (基准频率 / 2) × 0.9 = 140 625 000 Hz
FREF >  safe_limit  →  硬件四分频后测量，读数乘 4 还原
FREF <= safe_limit  →  直接测量
```

因此测量前必须用 `CONF:FREQ` 设定被测信号的大致频率，否则会用错分频档，
高频段会读出约 1/4 的值。上电默认 `FREF = 1000000`（1 MHz）。

上式中的基准频率取自 `GetClkFsFreq()`：`SIG:STATUS0?` 为 0 时用理想值 312.5 MHz，
阈值即 140.625 MHz；为 1 时改用 SD 卡校准值，阈值随之微调。

分频对精度没有影响 —— 分频后的上升沿就是输入的上升沿，回归精度由序列覆盖的时间跨度
决定，而跨度不变。上限约 350 MHz（受 `clk_fx` 时序约束限制）。

> 2026-08-17 前的行为：`FREF > safe_limit` 时走等精度法 + TDC 校正。该路径的不确定度是
> ±1 计数（350 MHz / 100 ms 闸门约 0.029 ppm），比时间戳法差约 800 倍。等精度硬件与软件
> 已于 2026-08-18 整体删除。上位机侧无需任何改动，命令与响应格式完全不变。

测量失败（时间戳条目少于 3 条）时返回 `0.00000\n`。

### 3.2 `MEAS:FREQ?` — 测量频率

与 `READ?` 完全等价，调用同一函数。

```
发送: MEAS:FREQ?\n
响应: 10000000.12345\n
```

## 4. 配置命令

### 4.1 `CONF:FREQ?` — 查询参考频率

```
发送: CONF:FREQ?\n
响应: 10000000\n
```

返回整数，单位 Hz。

### 4.2 `CONF:FREQ <值>` — 设置参考频率

```
发送: CONF:FREQ 10000000\n
响应: 无
```

| 参数 | 类型 | 单位 | 说明 |
|------|------|------|------|
| 值 | int | Hz | 被测信号的大致频率 |

该值仅用于选择测量模式和自适应 `edge_skip`，不影响测量结果的计算基准（基准来自 312.5 MHz 时钟）。

上位机若需确认设置成功，应随后发送 `CONF:FREQ?` 回读。

### 4.3 `FREQ:GATE:TIME?` — 查询闸门时间

```
发送: FREQ:GATE:TIME?\n
响应: +1.00000000000000E-001\n
```

| 字段 | 类型 | 格式 | 单位 |
|------|------|------|------|
| 闸门时间 | double | 53230A 科学计数法 | **秒** |

响应格式对齐 Keysight 53230A：正负号 + 1 位整数 + 小数点 + 14 位小数 + `E` + 指数符号 + **3 位**指数。
注意指数是 3 位，C 的 `%E` 默认只给 2 位，Python 的 `float()` 与多数语言的字符串转浮点均可直接解析。

| 闸门 | 响应 |
|------|------|
| 1 ms | `+1.00000000000000E-003` |
| 10 ms | `+1.00000000000000E-002` |
| 100 ms | `+1.00000000000000E-001` |
| 1 s | `+1.00000000000000E+000` |
| 10 s | `+1.00000000000000E+001` |

### 4.4 `FREQ:GATE:TIME <值>` — 设置闸门时间

```
发送: FREQ:GATE:TIME 1\n
响应: 无
```

| 参数 | 类型 | 单位 |
|------|------|------|
| 值 | double | **秒** |

设置与查询的单位都是**秒**。发送 `FREQ:GATE:TIME 1` 后，`FREQ:GATE:TIME?` 返回 `+1.00000000000000E+000`。

上电默认 100 ms。参数为任意浮点数，不限于特定档位——闸门时长由软件 `usleep` 实现，非硬件定时器分频。常用值：

| 输入（秒） | 闸门（ms） | 适用场景 |
|-----------|-----------|----------|
| 0.001 | 1 | 快速测量 |
| 0.01 | 10 | 中速 |
| 0.1 | 100 | 默认 |
| 1 | 1000 | 高精度 |
| 10 | 10000 | 超高精度 |

时间戳模式下闸门时间会被强制到至少 1 ms。

### 4.5 `PPM?` — 查询 PPM 范围

```
发送: PPM?

响应: +1.00000000000000E+000

```

与 `FREQ:GATE:TIME?` 相同的 53230A 科学计数格式：符号 + 1 位整数 + 14 位小数 + `E` + 符号 + 3 位指数。

### 4.6 `PPM <值>` — 设置 PPM 范围

```
发送: PPM 1.0

响应: 无
```

| 参数 | 类型 | 单位 |
|------|------|------|
| 值 | double | ppm |

上电默认 0。这是起振判据（见 7.6），普通测频通路不读取它。
**必须设为大于 0 的值**，否则 `STARTUP:TIME?` 返回 `-5`。

## 5. 信号控制命令

### 5.1 输出控制

三条命令格式一致，参数只能是单个字符 `0` 或 `1`，其他值（包括缺省参数）不做任何处理也不响应。

| 命令 | 控制的管脚 | 响应 |
|------|-----------|------|
| `SIG:PRIREF <0/1>` | CTR_PRIREF (W15) | `1\n` |
| `SIG:REFCLOCK <0/1>` | CTR_REF_CLOCK (V16) | `1\n` |
| `SIG:OCXO <0/1>` | CTR_OCXO (W16) | `1\n` |

```
发送: SIG:PRIREF 1\n
响应: 1\n
```

> **v2.1 及更早版本的本文档把该命令误写为 `SIG:PREF`**（缺少 `RI`）。
> 固件从未接受过这个拼写，发送 `SIG:PREF` 会被静默丢弃。
> 正确拼写是 `SIG:PRIREF`。若上位机照旧文档实现，此处需要修正。

响应固定为 `1`，表示命令已受理，不反映实际电平。上电后三者均被初始化为 1。

### 5.2 状态查询

| 命令 | 读取的管脚 | 响应 |
|------|-----------|------|
| `SIG:STATUS0?` | CTR_STATUS0 (W14) | `0\n` 或 `1\n` |
| `SIG:STATUS1?` | CTR_STATUS1 (W13) | `0\n` 或 `1\n` |
| `SIG:STARTT?` | CTR_START_T (J14) | `0\n` 或 `1\n` |

```
发送: SIG:STATUS0?\n
响应: 1\n
```

`SIG:STARTT?` 读的是起振测量的触发脚当前电平。它存在的唯一理由是诊断 ——
`STARTUP:TIME?` 返回 `-3` 时，用它区分「夹具没断开 VCC」和「引脚悬空被拉高」，
详见 7.8。**断开夹具 VCC 后应轮询这条命令直到返回 0，再发 `STARTUP:INIT`。**

**CTR_STATUS0 有额外含义**：它决定频率运算使用哪个基准值。

| STATUS0 | 基准频率来源 |
|---------|--------------|
| 1 | SD 卡 `FREQ.TXT` 中的校准值 |
| 0 | 理想值 312 500 000 Hz |

## 6. 校准命令

### 6.1 `CAL:REF:PREP` — 校准预备

把外部 10 MHz 从 PLL 上摘下来，只留给计数器。**校准前必须先发这一条。**

| 动作 | 结果 |
|------|------|
| `CTR_REF_CLOCK` | 置 1 |
| `CTR_PRIREF` | 置 0 |

```
发送: CAL:REF:PREP\n
响应: 1\n
```

**为什么必须**：板上这一路 10 MHz 除了进 FPGA 计数器，还接到 LMK5B12204 的
`PRIREF_P` / `PRIREF_N`。`CTR_PRIREF` 为 1 时 PLL 会把 312.5 MHz **锁到这个外部 10 MHz 上**，
此时再去测，读数必然是精确的 312.5 MHz，与 OCXO 的真实状态无关 —— 校准要找的那个偏差
恰好被锁没了，而 `CAL:REF?` 仍然会返回 `1`、仍然会把这个「完美」的数写进 SD 卡。

设备上电时 `CTR_PRIREF` 与 `CTR_REF_CLOCK` **都是 1**，所以刚开机的仪器一定要先执行本命令。

**注意事项**

- 命令本身只是两次寄存器写，立即返回；但 PLL 换参考源后需要时间重新稳定，
  固件不替上位机等待，请在本命令与 `CAL:REF?` 之间留出间隔。
- 等价于依次发送 `SIG:REFCLOCK 1` 和 `SIG:PRIREF 0`（见 5.1），单独成一条命令是为了
  让「校准预备」这件事在上位机侧只有一种写法，不会漏掉其中一路。
- 校准结束后如需恢复原来的参考源配置，用 5.1 的 `SIG:*` 命令自行设置；本命令不做恢复。

---

### 6.2 `CAL:REF?` — 用外部 10 MHz 校准基准时钟

把一路标准 10 MHz 信号接到 `clk_10m`（V5，LVCMOS33）后发送本命令。设备用时间戳引擎测这一路
信号，反推出内部基准时钟 `clk_fs` 的实际频率，写入 SD 卡根目录的 `FREQ.TXT`，并在本次运行中
立即采用。

**请求**

```
CAL:REF?\n
```

**前置条件一：必须先发过 `CAL:REF:PREP`**（见 6.1），否则 PLL 正锁在被测的那路 10 MHz 上，
测出来必然是精确的 312.5 MHz，校准形同虚设。固件**不检查**这一条 —— 那两个引脚是纯输出，
读回来只是软件自己刚写的值，证明不了 PLL 已经切换完毕。

**前置条件二：`CTR_STATUS0` 与 `CTR_STATUS1` 必须都为 1**，否则命令直接返回 `0`，
不做任何测量，也不改动 SD 卡上已有的值。可先用 `SIG:STATUS0?` / `SIG:STATUS1?` 确认。

**响应**

| 字段 | 类型 | 含义 |
|------|------|------|
| 结果 | int | `1` = 校准成功并已写入 SD 卡；`0` = 失败 |

```
发送: CAL:REF?\n
响应: 1\n
```

响应**不携带频率值**。它回答的是「仪器现在校准好了没有」，不是一个测量结果 ——
反推出的基准频率打印在串口。

**返回 `0` 的全部情况**，TCP 响应不区分，串口可查：

| 情况 | 串口提示 |
|------|----------|
| `CTR_STATUS0` / `CTR_STATUS1` 未同时为 1 | `[CAL] refused: CTR_STATUS0=... CTR_STATUS1=...` |
| 采集失败（没信号、DMA 超时等） | `[CAL] capture failed, rc=...` |
| 反推结果不在 312.49 ~ 312.51 MHz 之内 | `[CAL] rejected: clk_10m measured ... Hz, implied clk_fs outside ...` |
| 频率有效但 SD 卡写入失败 | `[CAL] ... write failed, value applied to this session only` |

最后一种情况下频率**已在本次运行中生效**，只是没能存下来，下次上电即丢失 —— 仍然按失败
处理并返回 `0`，因为「校准好了」意味着掉电重来也还在。

312.49 ~ 312.51 MHz 这道窗口（标称的 ±32 ppm）拦的是「没接信号 / 接错频率 /
烧的是不支持该功能的旧 bitstream」这三种会算出外观合理数字的情况 ——
一旦写进 SD 卡，此后每一次测频都会按错误基准整体偏移。

**注意事项**

- **固定用 1 秒闸门**，与 `FREQ:GATE:TIME` 的设置无关，命令内部临时覆盖后原样还回，
  不会影响之后的 `READ?` 或 `FREQ:GATE:TIME?`。实际耗时约 1.1 秒（4096 条样本略微溢出闸门），
  期间连接被占用。闸门写死是因为拟合精度取决于样本跨度，而这个结果要写进 SD 卡长期使用。
- `CTR_STATUS0` 同时也决定校准值是否参与频率运算（见 5.2），因此把它列为前置条件之后，
  「校准成功」与「校准值正在生效」就是同一件事。
- 命令会临时把测量源切到 10 MHz 通道，返回前恢复。不要与 `READ?` 并发下发。

---

### 6.3 `CAL:REF:VAL?` — 查询当前基准频率

返回频率运算当前实际使用的基准时钟频率，格式与 `FREQ:GATE:TIME?` 相同
（53230A 科学计数法：符号 + 1 位整数 + 14 位小数 + 3 位指数）。

| 字段 | 类型 | 格式 | 单位 |
|------|------|------|------|
| 基准频率 | double | 53230A 科学计数法 | Hz |

```
发送: CAL:REF:VAL?\n
响应: +3.12500000000000E+008\n
```

| 基准频率 | 响应 |
|----------|------|
| 312 500 000 Hz | `+3.12500000000000E+008` |
| 312 499 987 Hz | `+3.12499987000000E+008` |

**返回哪个值由 `CTR_STATUS0` 决定**（见 5.2）：

| CTR_STATUS0 | 返回 |
|-------------|------|
| 1 | SD 卡 `FREQ.TXT` 中的校准值（卡缺失或解析失败时为理想值） |
| 0 | 理想值 312 500 000 Hz |

也就是说，这条命令读的是**当前正在用的那个数**，不是**卡上存着的那个数**。
两者只在 `CTR_STATUS0` 为低时不同。校准成功后立刻查询会得到刚写入的新值 ——
`CAL:REF?` 要求 `CTR_STATUS0` 为 1 才执行（见 6.2），所以这种场景下两者必然一致。

## 7. 起振时间测量

用连续时间戳测晶振的起振时间。两条命令，因为触发发生在它们之间：
`STARTUP:INIT` 让下位机 arm 好 DMA 并开始监测 `CTR_START_T`（立即返回，无响应），
上位机随后合上夹具 VCC 把触发拉高，下位机从那一刻起连续采集 65535 条时间戳、
还原 f(t) 曲线、找出频率进入 `PPM` 容差带并保持住的时刻；
`STARTUP:TIME?` 把这个时刻取回来。

方法出处：Staffan Johansson, *Start-up Measurements on Oscillators — Using the
CNT-90/CNT-91 to Measure Oscillator Start-up*, Pendulum Instruments White Paper
No.2, Nov 2007。论文用一个电容把电源上升沿耦合进测量输入充当 time 0，
本机改用独立的 `CTR_START_T` 触发脚（J14）。

### 7.1 `STARTUP:SPAN?` — 查询采集跨度

```
发送: STARTUP:SPAN?

响应: 128.000
```

`%.3f` 格式，单位**毫秒**。

> 单位是毫秒，不是 `FREQ:GATE:TIME` 用的秒。`STARTUP:*` 这一组命令全部用毫秒，
> 与 `STARTUP:TIME?` 的返回单位一致。

### 7.2 `STARTUP:SPAN <值>` — 设置采集跨度

```
发送: STARTUP:SPAN 128

响应: 无
```

| 参数 | 类型 | 单位 | 范围 |
|------|------|------|------|
| 值 | double | ms | > 0，否则该值被忽略 |

**无响应**，与 `CONF:FREQ` / `FREQ:GATE:TIME` / `PPM` 一致。需要确认时用 `STARTUP:SPAN?` 回读。

上电默认 128 ms。

**这是目标值，不是精确值。** 固件按 `FREF` 反算 `EDGE_SKIP`，而 `EDGE_SKIP` 只能取整数，
所以实际跨度会向上取整到最近的可达值。实际用的 `EDGE_SKIP` 与实际跨度在串口打印。
详见 7.7。

### 7.3 `STARTUP:WIN?` — 查询目标时间分辨率

```
发送: STARTUP:WIN?

响应: 10.000
```

`%.3f` 格式，单位**微秒**。

> 单位是微秒，`STARTUP:SPAN` 是毫秒。两者在实际取值上差三个数量级，
> 写错会立刻表现为荒谬的窗口条数，被夹紧并在串口打印出来。

### 7.4 `STARTUP:WIN <值>` — 设置目标时间分辨率

```
发送: STARTUP:WIN 10

响应: 无
```

| 参数 | 类型 | 单位 | 范围 |
|------|------|------|------|
| 值 | double | µs | > 0，否则该值被忽略 |

上电默认 10 µs。**无响应**，需要确认时用 `STARTUP:WIN?` 回读。

这是**每算一次频率所覆盖的时间**，也就是起振时刻的定位精度（论文里的 measuring time）。
固件按 `N = STARTUP:WIN / Δt` 算出每个窗口的时间戳条数，其中 `Δt = 实际跨度 / 65535`。
**条数是推导出来的，不是配置的** —— 同样的条数在不同跨度下对应不同的时间分辨率，
把条数当参数就等于每次改跨度都在悄悄改分辨率。

**这是目标值，不是保证值。** 窗口至少要 8 条（少于这个数直线拟合几乎没有残差自由度，
而起振初期恰恰是噪声毛刺过门限最多的时候，会主导拟合），最多 4096 条。
被夹紧时串口会打印实际用的条数与实际分辨率。

**默认的 128 ms 跨度配 10 µs 是达不到的**：Δt = 1.95 µs，10 µs 只折合 5 条，
被抬到 8 条，实际分辨率落在 15.6 µs。要真正拿到 10 µs 必须缩短跨度，见 7.7。

### 7.5 `STARTUP:INIT` — 开始监测触发

```
发送: STARTUP:INIT

响应: 无
```

**纯写指令，不返回任何数据。** 下位机收到后立即把测量交给专用任务并返回，
随即开始监测 `CTR_START_T`。上位机不需要读、也读不到任何东西，
发完就可以去合夹具的 VCC。

**发出到真正开始监测触发之间约 1~2 ms**：任务还要 poison 512 KB 缓冲并 arm DMA。
上位机在 `STARTUP:INIT` 与合 VCC 之间**至少留 5 ms**。继电器动作本身通常就有
5~10 ms，一般自然满足，但用固态开关时要留意。

被拒绝时同样没有响应，原因**延迟到 `STARTUP:TIME?` 返回**（见 7.6 的错误码表），
同时打印在串口。拒绝的条件：

| 条件 | `STARTUP:TIME?` 随后返回 |
|---|---|
| `CTR_START_T` 此刻已经是高（夹具 VCC 没断开） | `-3.0000` |
| `CONF:FREQ` / `PPM` / `STARTUP:SPAN` / `STARTUP:WIN` 有未设或非正值 | `-5.0000` |
| 测量任务没能创建（上电时打印在串口） | `-9.0000` |

还有一种拒绝**不会**反映到 `STARTUP:TIME?`：上一次测量还没结束时又发了 `STARTUP:INIT`，
这条会被忽略，而 `STARTUP:TIME?` 返回的是**上一次**测量的结果。这是有意的 ——
报告这次拒绝就意味着把正在进行的测量丢掉。串口会打印一行提示。

> **`STARTUP:INIT` 之后到触发拉高之前，设备不响应网络。** 触发检出是一段不让出 CPU 的
> 忙轮询（优先级高于 lwIP），这是把 t = 0 的抖动压到微秒量级的代价 —— tick 是 10 ms，
> 让出一次就可能给毫秒级的起振时间引入 100% 误差。
> 这段时间上位机本来也只在操作夹具；提前发出的 `STARTUP:TIME?` 会滞留在 socket 里，
> 等测量结束后才被处理，结果不受影响。

### 7.6 `STARTUP:TIME?` — 取回起振时间

```
发送: STARTUP:TIME?

响应: 3.4720
```

`%.4f` 格式，单位**毫秒**，从 `CTR_START_T` 上升沿起算。

**阻塞命令**：一直等到测量算完才返回，所以合上 VCC 之后随时可以发，早发只是多等一会。
重复发送返回同一个结果，结果只被下一条 `STARTUP:INIT` 清掉。

负数是错误码，不是时长：

| 响应 | 含义 | 处置 |
|------|------|------|
| `-1.0000` | 采集正常，但在整个跨度内频率始终没有进入容差带 | 加大 `STARTUP:SPAN`，或放宽 `PPM` |
| `-2.0000` | `STARTUP:INIT` 之后 10 s 内 `CTR_START_T` 一直是低 | 检查触发线与夹具 |
| `-3.0000` | `STARTUP:INIT` 到达时 `CTR_START_T` 已经是高 | 夹具 VCC 没断开，见 7.8 |
| `-4.0000` | 采集本身失败（DMA 超时、序号断裂、传输不完整） | 看串口输出的具体原因 |
| `-5.0000` | `CONF:FREQ` / `PPM` / `STARTUP:SPAN` / `STARTUP:WIN` 有未设或非正值 | 补齐参数 |
| `-6.0000` | 之前没有发过 `STARTUP:INIT` | 按 7.9 的顺序重来 |
| `-7.0000` | 等了 40 s 仍没有结果 | 测量卡住，查串口 |
| `-9.0000` | 测量任务没能创建（FreeRTOS 堆不足），上电时串口已报 | 固件问题 |

`-4` 最常见的成因是**首个可检出边沿来得太晚**。采集超时按「实际跨度 × 2 + 5 s」设定，
其中 5 s 的裕量就是留给触发到首边沿这段死区的；比这更慢起振的器件会被判为采集失败，
而不是给出一个错误的时间。绝对上限来自 coarse 计数器：触发后 **13.7 s** 回绕，
超过之后时间轴会错乱。

上位机的 socket 超时必须大于 40 s（`-7` 的门限），否则会在固件放弃之前自己先超时。

前置条件（在 `STARTUP:INIT` 时检查）：

- `CONF:FREQ` 已设为晶振标称频率
- `PPM` 已设为大于 0 的容差
- `SIG:STATUS0?` 应为 1，即用 SD 卡校准过的基准。**判据是 ppm 级的，基准本身的偏差
  会原样进入判据** —— 判 1 ppm 而基准没校到 0.1 ppm，测的是基准不是 DUT

串口同时输出配置、f(t) 曲线（约 64 个点）、首个可检出边沿的时刻、以及本次实际达到的
频率分辨率。响应里只有起振时间这一个数。

### 7.7 覆盖能力与分辨率

条数固定 65535（`TS_PKT_LEN` 是 16 位，这是单次 simple mode 传输的硬上限），
于是相邻两条时间戳的间隔

```
Δt = 实际跨度 / 65535
```

**与被测频率无关**。窗口条数 `N = STARTUP:WIN / Δt`，实际时间分辨率 `W = N · Δt`，
频率分辨率

```
δ[ppm] = σ_t · √12 / (√N · W) × 10⁶ ,  σ_t ≈ 30 ps
```

因为 Δt 与频率无关，**N、W、δ 也都与频率无关**。同一张分辨率表对 512 kHz 的晶振
和 100 MHz 的晶振同样成立。频率只影响一件事：达到目标跨度所需的 `EDGE_SKIP`。

#### 跨度与 EDGE_SKIP

推算式：`EDGE_SKIP + 1 = ceil(f_x × 跨度 / 65535)`，默认 128 ms 下即 `ceil(f_x / 512 kHz)`

| 标称频率 | EDGE_SKIP | 实际跨度 | Δt |
|---|---|---|---|
| 32.768 kHz | 0 | 2.00 s | 30.5 µs |
| 100 kHz | 0 | 655 ms | 10.0 µs |
| 512 kHz | 0 | 128 ms | 1.95 µs |
| 1 MHz | 1 | 131 ms | 2.00 µs |
| 10 MHz | 19 | 131 ms | 2.00 µs |
| 50 MHz | 97 | 128 ms | 1.96 µs |
| 100 MHz | 195 | 128 ms | 1.96 µs |
| 200 MHz | 97 | 128 ms | 1.96 µs |

四点说明：

1. **512 kHz 是门槛，但低于它不是失败。** `EDGE_SKIP` 最小是 0，此时跨度变成
   65535 / f_x，只会**超过**目标而不会不足。32.768 kHz 自动得到 2 s 的覆盖 ——
   这恰好是音叉晶振需要的，128 ms 对它本来就不够。代价是 Δt 涨到 30.5 µs，
   10 µs 的时间分辨率在这个频率上根本达不到（最细 8 × 30.5 µs = 244 µs）。
2. **512 kHz ~ 5 MHz 之间跨度量化误差偏大。** `EDGE_SKIP + 1` 取整，
   768 kHz 时 1.5 只能取 2，实际跨度 171 ms（比目标多 33%）。10 MHz 以上误差
   降到几个百分点以内。串口会打印实际值。
3. **跨度从首个可检出边沿起算，不是从触发起算。** DUT 未上电时被测输入没有任何跳变，
   时间戳引擎一条都不产生，缓冲不被死区消耗。覆盖窗口是
   [t_first, t_first + 跨度]，自动跟随。这是时间戳法相对固定闸门法的结构性优势。
4. **200 MHz 一行走的是硬件四分频**（超过 140.625 MHz 时自动开启，与 `READ?` 同一规则），
   `EDGE_SKIP` 作用在分频后的边沿上。

#### 固定分辨率时，跨度越短越好

这一条与直觉相反，但直接从上面的公式来：固定 W，则 `N = W · 65535 / 跨度`，
跨度缩短使每个窗口装进更多条时间戳，δ 随 √N 改善。**没用来覆盖起振过程的跨度，
是白白换掉的频率分辨率。**

`STARTUP:WIN 10` 时（与被测频率无关）：

| `STARTUP:SPAN` | Δt | N | 实际 W | δ | 最低适用 f_x |
|---|---|---|---|---|---|
| 6.5 ms | 99 ns | 101 | 10.0 µs | **1.03 ppm** | 10.1 MHz |
| 13 ms | 198 ns | 50 | 9.9 µs | 1.48 ppm | 5.0 MHz |
| 33 ms | 504 ns | 20 | 10.1 µs | 2.31 ppm | 2.0 MHz |
| 66 ms | 1.01 µs | 10 | 10.1 µs | 3.26 ppm | 1.0 MHz |
| 128 ms | 1.95 µs | 5 → 夹到 8 | **15.6 µs** | 2.35 ppm | 512 kHz |

「最低适用 f_x」= 65535 / 跨度。低于它时 `EDGE_SKIP` 已经是 0，实际跨度只会更长，
这一行的 Δt / N / W / δ 都不再成立。

#### 判据严格时该把 WIN 设多大

反过来，如果 `PPM` 判据卡得很紧，就得放宽时间分辨率。默认 128 ms 跨度下
（Δt = 1.95 µs）：

| `STARTUP:WIN` | N | 实际 W | δ | 可用的判据 |
|---|---|---|---|---|
| 10 µs | 5 → 8 | 15.6 µs | 2.35 ppm | 5 ppm 以上 |
| 31 µs | 16 | 31.3 µs | 0.83 ppm | 2 ppm 以上 |
| 62 µs | 32 | 62.5 µs | 0.29 ppm | 1 ppm，余量 3.4 倍 |
| 125 µs | 64 | 125 µs | 0.10 ppm | 1 ppm，余量 10 倍 |

**判据 `PPM` 应当至少是 δ 的 2 倍**，否则判定时刻由噪声决定而不是由器件决定。
`PPM ≤ δ` 时串口会打印一条提示。

#### 有一个物理下限，加缓冲也突破不了

Δt 的下限是 1/f_x（`EDGE_SKIP = 0`），代入得

```
δ_min = σ_t · √12 / (√(W · f_x) · W) × 10⁶
```

10 MHz 器件、W = 10 µs 时 **δ_min = 1.04 ppm**。这由 σ_t 和被测频率决定，
与缓冲大小无关 —— 换 Scatter-Gather DMA 也只能让「小 Δt」和「长跨度」同时成立，
不会改善这个数。所以「10 µs 分辨率 + 1 ppm 判据」在 10 MHz 器件上凑不齐。

> 上面所有 δ 按 σ_t ≈ 30 ps 推算，而该值是从 README 里 **64 抽头**版本的实测数据
> 反推的。64 抽头只覆盖 3.2 ns 基准周期的 42%，大量样本饱和在链尾、相位信息丢失，
> 这本身就在抬高 σ_t。**256 抽头版本尚未上板验证**，全周期覆盖后量化误差为
> 21/√12 ≈ 6 ps，σ_t 有望降到 10~15 ps，上面所有 δ 随之改善 2~3 倍。
> 上板并重做码密度标定是把这些数字从估算变成实测的前提。

### 7.8 触发的电平语义（必读）

`CTR_START_T` 读的是**电平**，不是边沿。典型夹具里它就跟着 DUT 的 VCC 走：
VCC 断开时为低，VCC 合上瞬间拉高。由此产生三条硬性要求：

1. **必须先断开 DUT 的 VCC，再发 `STARTUP:INIT`，最后合 VCC。** 顺序反了，
   t = 0 就变成 `STARTUP:INIT` 到达的时刻而不是上电时刻。固件检出这种情况会拒绝测量，
   `STARTUP:TIME?` 返回 `-3`，而不是给出一个看起来正常的错误结果。
2. **每次测量之间必须让 `CTR_START_T` 回到低电平**，否则下一次 `STARTUP:INIT` 立刻被拒。
   夹具断开 VCC 时这一条自动满足。
3. 触发信号保持到被检出即可（忙轮询下 ≥ 10 µs 足够），实务上会保持到测量结束 ——
   VCC 本来就得一直供着。

t = 0 的不确定度约 1~3 µs：触发检出用不让出 CPU 的忙轮询（单次 AXI-Lite 读几百纳秒），
检出后只有两次 AXI 写就锚定零点。这是可标定的系统性偏置 ——
用示波器同时看 `CTR_START_T` 与某个 GPIO 翻转即可标定一次并从结果中扣除。

夹具侧还有两项系统偏置需要一并标定：VCC 上升沿从 0 爬到 `CTR_START_T` 输入门限所需的时间，
以及 VCC 到 DUT 与到 `CTR_START_T` 两条走线的相对延迟。两者都进入 t = 0，
且都是可重复的，标定一次即可扣除。

> **电气注意**：`CTR_START_T` 是 J14，LVCMOS25 电平。若夹具的 DUT VCC 是 3.3 V 或更高，
> **不能直接接到该管脚**，需要分压或电平转换。本文档看不到夹具原理图，此处仅作提醒。

#### `STARTUP:TIME?` 返回 `-3` 时的排查

`-3` 表示 `STARTUP:INIT` 到达时 `CTR_START_T` 读到高电平。用 `SIG:STARTT?` 直接看引脚：

**断开夹具 VCC，然后发 `SIG:STARTT?`。**

| 读到 | 说明 | 处置 |
|---|---|---|
| 立刻是 `0` | 引脚正常 | 那么 `-3` 是时序问题：`STARTUP:INIT` 发得太早，见下 |
| 等一会儿变成 `0` | 电源轨在放电 | 上位机改为**轮询到 0 再发 `STARTUP:INIT`** |
| 一直是 `1` | 引脚没有被拉低 | 夹具问题，见下 |

三种成因，按常见程度：

1. **供电轨放电需要时间。** 断开 VCC 不等于节点立刻到地 —— DUT 的去耦电容加上负载
   决定了衰减速度，从 2.5 V 跌到 LVCMOS25 的输入门限（约 1.7 V）可能要几毫秒到几百毫秒。
   上位机若断开后立即发 `STARTUP:INIT`，读到的仍是高。
   **修法**：断开后轮询 `SIG:STARTT?` 直到 `0`，再发 `STARTUP:INIT`。
2. **断开后引脚悬空。** 若夹具只是切断 VCC 而没有把该节点下拉到地，J14 就处于高阻态，
   读数不确定，且常因走线耦合或内部保持而读作 `1`。
   **修法**：在 `CTR_START_T` 节点上加一个下拉电阻（几 kΩ 到 10 kΩ），
   或让继电器在断开时把该节点切到地。这同时也让 t = 0 的边沿更干净。
3. **上一轮测量结束后没断开 VCC。** 每轮之间必须回到低电平，见本节第 2 条。

轮询版的序列：

```
[电信号] 断开夹具 VCC
SIG:STARTT?                →  1     还没放完电
SIG:STARTT?                →  1
SIG:STARTT?                →  0     可以了
STARTUP:INIT                     （无响应）
```

### 7.9 完整测量序列

```
上位机                                  下位机 / 夹具
─────────────────────────────────────────────────────────
*IDN?                              →   HALLIWAY,FREQ-COUNTER,C1804,...
SIG:STATUS0?                       →   1          基准已校准
CONF:FREQ 10000000                                晶振标称频率
PPM 3                                             容差 3 ppm
STARTUP:SPAN 33                        （无响应）采集跨度 ms
STARTUP:WIN 10                         （无响应）时间分辨率 µs

[电信号] 断开夹具 VCC                     CTR_START_T → 0
SIG:STARTT?                        →   0          确认放电到位，非 0 就重试

STARTUP:INIT                           （无响应）下位机开始监测触发
                                        ⚠ 至少等 5 ms

[电信号] 合上夹具 VCC                     CTR_START_T → 1，测量从这一刻起算

STARTUP:TIME?                      →   3.4720     起振时间，ms（阻塞到算完）

[电信号] 断开夹具 VCC                     为下一轮复位触发
```

配置类命令（`CONF:FREQ` 到 `STARTUP:WIN`）只在参数变化时发一次，逐个样品测试时
每轮只需要 断 VCC → 轮询 `SIG:STARTT?` 到 0 → `STARTUP:INIT` → 合 VCC →
`STARTUP:TIME?` 五步。

**`SIG:STARTT?` 那一步不要省。** 供电轨的放电不是瞬时的，断开后立即发 `STARTUP:INIT`
很可能仍读到高电平，测量被拒，`STARTUP:TIME?` 返回 `-3`。

两处时序要求：

- `STARTUP:INIT` 与合 VCC 之间 **≥ 5 ms**（下位机要 poison 512 KB 缓冲并 arm DMA，
  约 1~2 ms）
- 断 VCC 之后要等 DUT 放电充分再开始下一轮，建议 **≥ 30 s** 或等到电源跌至 50 mV 以下。
  残余电荷会显著缩短下一次测到的起振时间

上位机 socket 超时设为 **≥ 45 s**（`STARTUP:TIME?` 自身的放弃门限是 40 s）。

批量测试的建议：每个样品重复 10 次，报**中位数与极差**而不是均值 ——
起振时间的分布常有长尾。供电上升沿斜率、负载电容和温度都显著影响结果，
同一批测试必须固定。

## 9. 使用示例

### 9.1 Python

```python
import socket

class FreqCounter:
    def __init__(self, ip='192.168.1.115', port=5025, timeout=5.0):
        self.sock = socket.create_connection((ip, port), timeout=timeout)
        self.sock.settimeout(timeout)

    def _send(self, cmd):
        """发送不期待响应的命令"""
        self.sock.sendall((cmd + '\n').encode())

    def _query(self, cmd):
        """发送并读取一行响应"""
        self.sock.sendall((cmd + '\n').encode())
        return self.sock.recv(1024).decode().strip()

    def idn(self):
        return self._query('*IDN?')

    def set_fref(self, hz):
        self._send(f'CONF:FREQ {int(hz)}')
        return int(self._query('CONF:FREQ?'))    # 回读确认

    def set_gate(self, seconds):
        self._send(f'FREQ:GATE:TIME {seconds}')
        return float(self._query('FREQ:GATE:TIME?'))   # 返回秒，科学计数法

    def measure(self, gate_sec=None):
        if gate_sec:
            self.sock.settimeout(gate_sec + 0.5)
        return float(self._query('READ?'))

    def close(self):
        self.sock.close()


if __name__ == '__main__':
    fc = FreqCounter()
    print('设备:', fc.idn())

    fc.set_fref(10_000_000)          # 10 MHz，走时间戳法
    gate_ms = fc.set_gate(1)         # 1 秒闸门
    print(f'闸门: {gate_ms} ms')

    print(f'频率: {fc.measure(gate_sec=1):.5f} Hz')
    print('STATUS0:', fc._query('SIG:STATUS0?'))

    fc.close()
```

```csharp
using System;
using System.IO;
using System.Net.Sockets;

class FreqCounterClient : IDisposable
{
    private readonly TcpClient client;
    private readonly StreamReader reader;
    private readonly StreamWriter writer;

    public FreqCounterClient(string ip = "192.168.1.115", int port = 5025)
    {
        client = new TcpClient(ip, port);
        var stream = client.GetStream();
        stream.ReadTimeout = 5000;
        reader = new StreamReader(stream);
        writer = new StreamWriter(stream) { AutoFlush = true, NewLine = "\n" };
    }

    public void Send(string cmd) => writer.WriteLine(cmd);

    /// <summary>发送并读取一行响应</summary>
    public string Query(string cmd)
    {
        writer.WriteLine(cmd);
        return reader.ReadLine()?.Trim();
    }

    public double Measure() => double.Parse(Query("READ?"));

    public void Dispose() => client?.Close();
}

{

    Console.WriteLine("参考频率: " + fc.Query("CONF:FREQ?"));
    Console.WriteLine($"频率: {fc.Measure():F5} Hz");
}
```

## 10. 上位机实现要点

1. **区分「无响应」与「超时」**。参照 1.5 的分类，对无响应命令不要等待读取；需要确认时用对应的查询命令回读。

2. **命令名必须完整，含尾部问号**。大小写和空格数量已不敏感，但漏掉 `?` 或拼错命令名仍会被静默丢弃，表现为「超时」，容易误判为设备故障。特别注意 `SIG:PRIREF` 的拼写（见 5.1）。

3. **测量前先设 `FREF`**。它决定是否开启硬件四分频，设错会显著影响精度。

4. **注意单位换算**。`FREQ:GATE:TIME` 设置与查询都用秒（查询为 53230A 科学计数法）。

5. **连接管理**。每个连接由独立 FreeRTOS 任务处理，可建立多个连接，但设备资源有限，且命令处理共享全局状态（`FREF`、`GATE_TIME` 等）与同一接收缓冲，测量过程也没有互斥保护——**并发下发命令会导致结果错乱**。请只维持单一连接、串行下发。发送 `quit` 主动断开。

6. **`READ?` 是阻塞的**，占用时间约等于闸门时间。长闸门（10 秒）时务必放大 socket 超时。

7. **起振测量是两段式的，顺序不能变**：断 VCC → `STARTUP:INIT`（不读响应）→ 等 ≥ 5 ms
   → 合 VCC → `STARTUP:TIME?`。`STARTUP:INIT` 之后到触发拉高之前设备不响应网络，
   这是压低 t = 0 抖动的代价，属正常现象。socket 超时设 ≥ 45 s。完整流程见 7.9。

## 12. 常见问题

**Q1: 发送命令后没有响应？**

先对照 1.5 确认该命令是否本来就无响应。若属于有响应类，检查：

- 命令名是否完整，**尾部问号有没有漏**（`MEAS:FREQ` 无效，`MEAS:FREQ?` 才有效）
- 是否以 `\n` 结尾
- `SIG:PRIREF` 是否误写成了 `SIG:PREF`（旧版文档的错误，见 5.1）

大小写和空格数量自 v3.0 起不再是问题。

**Q2: 测量结果不准确？**

- `FREF` 是否设置正确（决定测量模式）
- 闸门时间是否过短
- `SIG:STATUS0?` 是否为 1（是否启用了 SD 卡校准值）
- SD 卡 `FREQ.TXT` 中的校准值是否与实际 OCXO 输出一致

**Q3: 返回 `0.00000`？**

时间戳模式下 FIFO 采集到的边沿少于 3 条，通常意味着被测信号缺失、幅度不足或频率远低于预期。

**Q4: 闸门时间只能取固定档位吗？**

不是。闸门由软件延时实现，可设任意值。但精度受 FreeRTOS 调度影响，并非硬件定时。

**Q5: 串口能用吗？**

当前不能。命令解析已与网口统一（v3.0），但 `main.c` 仍未调用 `init_uart()` 和 `uart_cycle()`，
串口中断与轮询都没有启动。接入这两个调用后即可使用，命令集与本文档完全一致。
串口参数：9600 8N1（`uart.c` 中 `XUartPs_SetBaudRate` 设定）。

**Q6: 多个上位机同时连接会怎样？**

固件允许多连接，但接收缓冲、配置状态和测量硬件都是共享的且无互斥。
两个连接同时下发命令会互相干扰（闸门被打断、参数被覆盖）。请只用单一连接。

# 被测信号四分频改造方案

**状态**：RTL / C / 文档改动已完成，**未经综合与上板验证**（本机无工具链）
**日期**：2026-08-17

## 1. 目标

高频段（`FREF > safe_limit`）**弃用等精度 + TDC 法**，改为：在 `Counter_Core` 内对被测信号
四分频，仍走时间戳 + 最小二乘回归，软件把结果乘 4 还原。

现状（`freq_counter_core.c:919`）：

```
FREF >  safe_limit (140.625 MHz)  →  ReadFr_EqualPrecision()
FREF <= safe_limit                →  ReadFr_TimestampMode()
```

改造后：两条分支都走 `ReadFr_TimestampMode()`，区别只是是否打开硬件分频。

## 2. 为什么值得改

### 2.1 等精度法的精度天花板由 ±1 计数决定

等精度法的相对不确定度 ≈ `1 / (f_x × T_gate)`。350 MHz / 100 ms 闸门 → **0.029 ppm**，
与 `interface_spec.md` 7.1 的实测值（100 ms 闸门 0.029 ppm）完全吻合，说明当前等精度
结果就是纯 ±1 量化，没有从 TDC 校正里拿到任何好处。

原因写在 `interface_spec.md` 7.2：闸门 TDC 值实测不可信（`tdc_test_rise` 曾 90% 饱和），
`TDC_CORRECTION_ENABLED` 的启用条件（256 抽头上板 + 码密度标定）至今没满足。
也就是说"等精度 + TDC"里的 TDC 这一半从未真正生效过。

### 2.2 时间戳法的精度由时间跨度决定，与被测频率无关

实测（`interface_spec.md` 7.1.1）：110 ms 跨度下 σ = 0.000022 ppm（5 MHz）/
0.0000375 ppm（99 MHz）。**比等精度法好约 800 倍**，而且耗时相同。

分频不会削弱这个优势，见第 5 节。

### 2.3 顺带解决输入占空比问题

`ts_engine` 把 `clk_fx` 当**数据**在 `clk_fs` 域采样，要求高电平和低电平各自都长于一个
`clk_fs` 周期（3.2 ns）。占空比严重偏离 50% 的高频输入即使频率低于奈奎斯特也会漏边沿。
四分频输出取自计数器的 bit1，无论输入占空比如何，输出恒为 50% 方波。

## 3. 硬件改动

### 3.1 分频器位置：`counter_core.v` 内联，不新建文件

```
Counter_Core_v1_0.v          IBUFDS + BUFG  →  clk_fx（原始，全局时钟网）
└── counter_core.v           ★ 新增 /4 计数器 + 二选一
    ├── ts_engine.v          .clk_fx ← 分频后信号（可选）
    └── eq_counter.v         .clk_fx ← 原始 clk_fx（不变）
```

**为什么内联而不是新建 `src/prescaler.v`**：新增源文件要改 `component.xml` 的文件清单，
而 `component.xml` 有三份副本、改完必须让 Vivado 重新打包并 Generate Output Products
（见记忆 `project-counter-ip-source-copies`）。内联 12 行代码则**完全不动 IP 的端口和
参数**，`.xci`、`synth/` 包装器、`component.xml` 一概不用碰，可以走"cp 到三处副本"的快速路径。

RTL 草案（`counter_core.v`，插在控制位跨域之后、`ts_engine` 实例化之前）：

```verilog
    //========================================================================
    // Divide-by-4 prescaler for the signal under test
    //
    // Above the clk_fs Nyquist limit the engine cannot see every edge of
    // clk_fx: ts_engine samples it as data in the clk_fs domain, so a level
    // shorter than one clk_fs period may be missed entirely. Dividing by 4
    // brings such inputs back inside that window and keeps the timestamp path
    // -- which is about 800x better than the equal-precision fallback -- usable
    // at those frequencies.
    //
    // No timing information is lost: div_cnt[1] toggles on a rising edge of
    // clk_fx, so every rising edge of the divided signal IS an input rising
    // edge, delayed by one flop. That delay is constant and drops out of the
    // least-squares slope; software only multiplies the result by 4.
    //
    // Only ts_engine takes the prescaled signal. eq_counter keeps the raw
    // clk_fx because it uses it as a clock, and driving a clock from fabric
    // logic would need a BUFG plus a generated-clock constraint -- for a path
    // that is no longer used for measurement.
    //
    // div4_en is used combinationally, not latched on the capture start edge
    // like edge_skip. Software must therefore only change PRESCALE while
    // TS_EN is low; writing it mid-capture corrupts the run in progress.
    //========================================================================
    reg [1:0] div_cnt;
    always @(posedge clk_fx) begin
        if (!rst_fx_n) div_cnt <= 2'd0;
        else           div_cnt <= div_cnt + 1'b1;
    end

    wire fx_ts = div4_en ? div_cnt[1] : clk_fx;
```

`ts_engine` 实例的 `.clk_fx (clk_fx)` 改为 `.clk_fx (fx_ts)`。

### 3.2 已知代价：二选一 LUT 进入了测量路径

改造后 `fx_ts` 由一个 LUT 驱动，而不是直接来自 BUFG。它同时接到 TDC 延迟链的 `CYINIT`
和 `fx_sync[0]`：

- **固定插入延迟无害**：频率由回归斜率给出，共模常数偏移完全抵消。
- **需要实测确认的是抖动**：全局时钟网走到通用布线，可能给 `sigma_t`（当前 21 ps）
  添上几 ps。验收判据见第 8 节 —— 用 5 MHz、`DIV4=0` 复测 σ，与 0.000022 ppm 对比。
- **备选方案（暂不采用）**：用 `BUFGMUX_CTRL` 切换，输出仍在全局时钟网上。代价是引入
  generated clock、要加 `create_generated_clock` 和选择端同步器。只有在上一条实测退化
  时才值得做。

### 3.3 新寄存器 `PRESCALE` (0x30)

| 偏移 | 名称 | 访问 | 说明 |
|------|------|------|------|
| 0x30 | `PRESCALE` | R/W | bit0 = `DIV4_EN`，1 = 被测信号四分频后送时间戳引擎；其余位保留 |

**为什么不用 `CTRL` 的空闲位**：现有软件对 `CTRL` 全是绝对写
（`core_wr(CTRL, COUNTER_CORE_CTRL_TS_EN)`），不是读改写。分频位放进 `CTRL`，
`CaptureTimestamps()` 里那几次 `core_wr(CTRL, ...)` 会顺手把它清掉，而现象是"高频测出来
差 4 倍"——很难一眼看出。独立寄存器杜绝这类耦合。

`Counter_Core_v1_0_S_AXI.v` 的改动：

```verilog
    localparam [3:0] A_PRESCALE  = 4'hC;   // 0x30 R/W        // 新增
    localparam [31:0] VERSION_MAGIC = 32'h4343_0101;          // 0100 -> 0101
    reg [31:0] reg_prescale;                                  // 新增
    assign div4_en = reg_prescale[0];                         // 新增端口
```
写通道 case、读通道 case、复位赋值各加一条，照 `A_PKT_LEN` 的样子写。

### 3.4 版本号 0x43430100 → 0x43430101

`init_freqcounter()` 对 `VERSION` 做**相等**检查，不匹配就返回 −1。必须改，理由不是形式主义：
新软件配旧比特流时，`PRESCALE` 写到不存在的地址会被静默忽略，高频测量结果直接差 4 倍且
所有自检判据都通过。版本号是唯一能在启动时拦住这种组合的东西。

改动点三处：`Counter_Core_v1_0_S_AXI.v` 的 `VERSION_MAGIC`，以及下面两份
`Counter_Core.h` 的 `COUNTER_CORE_VERSION_MAGIC`。

### 3.5 XDC 不需要改动

- `div_cnt` 在 `clk_fx` 域内，已被 `create_clock -period 2.857 clk_fx` 覆盖。
- `fx_ts` → `tap_reg/D`：已有 `set_false_path`（第 76 行）。
- `fx_ts` → `fx_sync[0]`：`clk_fx`/`clk_fs` 已在 `set_clock_groups -asynchronous` 里。
- `div4_en`（`clk_fpga_0` 域）→ 上述两处：同样落在 async 分组内。
- 分频信号**不作为时钟使用**，所以不产生 generated clock，不需要 `create_generated_clock`。

## 4. 软件改动

### 4.1 `Counter_Core.h`（**三份**都要改）

| 路径 | 角色 |
|------|------|
| `ip_repo/.../drivers/Counter_Core_v1_0/src/Counter_Core.h` | 源，BSP 重新生成时从这里复制 |
| `top_cymometer.sdk/FreqCounterOS_bsp/ps7_cortexa9_0/include/Counter_Core.h` | 应用代码的 include 路径 |
| `top_cymometer.sdk/FreqCounterOS_bsp/ps7_cortexa9_0/libsrc/Counter_Core_v1_0/src/Counter_Core.h` | **BSP 库自己编译用的** |

第三份容易漏。`Counter_Core_selftest.c` 与它同目录、include 的是它，而自检里也检查
`COUNTER_CORE_VERSION_MAGIC` —— 只改前两份的话，`COUNTER_CORE_Reg_SelfTest()` 会在
新比特流上报版本不匹配。

```c
#define COUNTER_CORE_PRESCALE_OFFSET    0x30u   /* R/W input prescaler */
#define COUNTER_CORE_PRESCALE_DIV4      (1u << 0)  /* divide clk_fx by 4 */
#define COUNTER_CORE_PRESCALE_RATIO     4u      /* the fixed divide ratio */
#define COUNTER_CORE_VERSION_MAGIC      0x43430101u   /* was 0x43430100 */
```

### 4.2 `ReadFr_TimestampMode()` —— 分频决策收在这里

分频判据、`PRESCALE` 写入、边沿数折算、结果还原四件事必须成套出现，放同一个函数才不会
被拆散。`ReadFr()` 直接调用它的地方（`init_freqcounter():282`）也就自动跟着正确。

```c
int ReadFr_TimestampMode(char *Freq)
{
    u32 prescale, safe_limit;
    ...
    f_s = GetClkFsFreq();

    /* Above the Nyquist limit the engine cannot see every edge, so the input is
       divided by 4 in hardware and the result scaled back up. */
    safe_limit = (u32)((double)(f_s / 2u) * 0.9);
    prescale = ((u32)FREF > safe_limit) ? COUNTER_CORE_PRESCALE_RATIO : 1u;

    core_wr(COUNTER_CORE_PRESCALE_OFFSET,
            (prescale > 1u) ? COUNTER_CORE_PRESCALE_DIV4 : 0u);

    /* Edges reaching the engine are the divided ones */
    expected_edges = ((double)FREF / (double)prescale) * (GATE_TIME / 1000.0);
    ...                                     /* edge_skip / entries 计算不变 */
    freq *= (double)(edge_skip + 1u) * (double)prescale;   /* 还原 */
}
```

`PRESCALE` 必须写在 `CaptureTimestamps()` 之前——那个函数末尾才拉高 `TS_EN`，顺序天然满足。

### 4.3 `ReadFr()` 退化为直通

```c
int ReadFr(char *Freq)
{
    /* The equal-precision path is no longer used for measurement: with the
       hardware prescaler the timestamp path covers the full range, and it is
       about 800x more precise at the same gate time. ReadFr_EqualPrecision
       remains for START_T and RepeatTest. */
    return ReadFr_TimestampMode(Freq);
}
```

### 4.4 显式写 `PRESCALE = 0` 的地方

`PRESCALE` 是持久寄存器。`ReadFr` 在高频下把它置成 /4 之后，任何不管它的函数都会悄悄
测到分频信号。所以下列函数开头都要显式清零：

| 位置 | 原因 |
|------|------|
| `init_freqcounter()` | 上电确定初态 |
| `TimestampTest()` | 诊断必须看原始信号 |
| `tdc_collect_histogram()` | 码密度标定必须用原始边沿。这个静态辅助函数是 `TdcHistogramTest()` 与 `PrintTdcCalibTable()` 的共同入口，清一处即覆盖两者 |

实现为静态辅助函数 `set_prescale(u32 ratio)`（`ratio` 取 1 或 4），避免在四处重复
"比值 → 寄存器位"的映射。

### 4.5 不动的部分

- `scpi.c` 完全不动。`CONF:FREQ` 的语义不变，仍是"告诉仪器被测信号大概多少 Hz"。
- `ReadFr_EqualPrecision()` / `RunEqualPrecision()` / `eq_effective_count()` 保留，
  `ReadStartT()` 和 `RepeatTest()` 还在用。
- `eq_counter.v` 及其 TDC、`GATE_LEN` / `EQ_*` / `TDC_GATE` 寄存器全部保留。

### 4.6 协议文档要跟着改

`protocols/上位机通信协议.md:155-163` 那段模式选择说明要重写：不再是"两种算法"，
而是"同一种算法，高频段自动插入硬件四分频"。上位机行为不变。

## 5. 精度分析：四分频为什么不损失精度

回归斜率的相对不确定度（`interface_spec.md` 5.1）：

```
相对精度 ∝ sigma_t / 时间跨度
```

分频对这两项的影响：

| 量 | 分频后 | 说明 |
|----|--------|------|
| `sigma_t` | 不变（21 ps） | 分频输出的上升沿就是输入的上升沿，只多一级 FF 固定延迟 |
| 时间跨度 | 不变 | 4096 条样本铺满同一个闸门，靠 `EDGE_SKIP` 调节，只是分频后 `EDGE_SKIP` 小了 4 倍 |
| 样本数 | 不变（4096） | |

所以分频后的精度 = 同跨度下不分频的精度。以 350 MHz / 100 ms 闸门为例：

```
f_div         = 87.5 MHz
expected_edges = 8.75e6  →  EDGE_SKIP = 2372
实际跨度       = 4096 × 2373 / 87.5 MHz = 111 ms
```

跨度与 99 MHz 那一档（111 ms，σ = 0.0000375 ppm）相同，预期精度同量级，
对比等精度法的 0.029 ppm 好约 800 倍。

**关键点**：`(edge_skip+1) × prescale` 才是"每条时间戳跨过多少个输入周期"。软件把
`freq` 乘回这两个因子，量化误差不会被放大——被放大的是频率值本身和它的绝对误差，
相对误差不变。

## 6. 量程与限制因素

四个约束按紧到松排列：

| # | 约束 | 上限（`FREF`） | 说明 |
|---|------|----------------|------|
| 1 | XDC `clk_fx` 约束 2.857 ns | **350 MHz** | 当前实际上限。`eq_counter` 仍跑原始 `clk_fx`，要更高必须收紧约束并确认 32 位计数器收敛 |
| 2 | TDC 链跨度 5.376 ns（256 × 21 ps） | ~372 MHz | 分频后半周期必须长于链跨度，否则链里同时存在上一个下降沿和本次上升沿，温度计码被污染 |
| 3 | `clk_fs` 电平采样 / 奈奎斯特 | 562.5 MHz | 分频后 ≤ 140.625 MHz |
| 4 | BUFG 最高频率（-1 器件） | ~460 MHz（待查 DS187 确认） | 物理天花板 |

**四分频恰好是够用的最小 2 的幂**：350 MHz 二分频得 175 MHz > 140.6 MHz 奈奎斯特，不行；
四分频得 87.5 MHz，半周期 5.71 ns，刚好越过 5.38 ns 的链跨度（余量 6%）；八分频可行但
白白少 2 倍边沿率。

下限：`FREF` 略高于 140.625 MHz 时分频到 35.2 MHz，远在时间戳法舒适区内，两段衔接连续。

**约束 2 值得单独留意**——它在改造前就存在。`interface_spec.md` 7.1.1 记的
"99 MHz 的 σ 比 5 MHz 差 1.7 倍、`tdc` 取值范围只有 4~31"，很可能就是这条：99 MHz 半周期
5.05 ns < 5.38 ns，链里本来就有残留。分频反而让高频段的 TDC 质量比现在的 99 MHz 更好。

带宽方面：`ReadFr` 路径永远按闸门反算 `EDGE_SKIP`，不会撞 HP0 带宽。只有诊断用的
`TimestampTest(4096, 0)` 在 87.5 MHz 下是 700 MB/s，贴着上限（`interface_spec.md` 7.1.2），
但诊断函数已按 4.4 节清零 `PRESCALE`，不会走到这里。

## 7. 待决策：`eq_counter` 要不要一起删

"弃用等精度法"有两种力度，本方案取**保守解**（只从 `ReadFr` 分派里移除，硬件保留），
因为：

- `ReadStartT()` / `InitStartT()`（晶振起振时间测量，见 `doc/晶振起振时间测量方案.md`）
  用的是等精度短闸门，删了就得先在时间戳路径上重做。
- `RepeatTest()` 是现成的重复性诊断。
- 等精度法不受奈奎斯特限制，作为高频段的交叉验证手段仍有价值——两条独立通路
  测同一个信号，是发现分频接线错误的最直接办法。

**激进解**的收益：删掉 `eq_counter` 后 `clk_fx` 域只剩 2 位分频计数器，约束 1 消失，
上限抬到约束 2 的 372 MHz。代价是重做 START_T。

**建议**：先按保守解上板，确认 350 MHz 段可用；若后续确实需要 350–372 MHz，再单独立项处理
START_T 的迁移。

|----|------|------|
| 无回归 | 5 MHz，`FREF=4999700`，`ReadFr` ×100 | `PRESCALE` 读回 0；σ 与 0.000022 ppm 同量级（LUT 抖动检查，第 3.2 节） |

| 软硬配对 | 200 MHz，`FREF=200000000`，走 `ReadFr` | 返回 ≈ 200 MHz，**不是** 50 MHz —— 确认软件乘 4 与硬件除 4 成对生效 |

| 交叉验证 | 同上 | 与 `ReadFr_EqualPrecision()` 结果在 0.03 ppm 内一致（等精度法自身精度就是这个量级） |
| 量程上限 | 350 MHz | 时序报告 `clk_fx` 域收敛；测量结果稳定 |
| 诊断不受污染 | 高频测完紧接 `TimestampTest` | 测到的是原始信号频率，不是 1/4 |

`delta` 那一项是最灵敏的判据：`interface_spec.md` 7.1 里 5 MHz 的 62.5 就是靠它确认
粗计数与边沿检测对齐正确的，分频后它应精确变成 250.0。

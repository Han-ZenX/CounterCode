# 晶振起振时间测量方案（时间戳法）

**版本** 1.0　**日期** 2026-08-17　**状态** 已作废 —— 启动时间测量功能已于 2026-08-18 随等精度路径一并删除，见 [等精度与TDC闸门校正删除说明](等精度与TDC闸门校正删除说明.md)。本文保留为历史记录

参考：Staffan Johansson, *Start-up Measurements on Oscillators — Using the CNT-90/CNT-91 to
Measure Oscillator Start-up*, Pendulum Instruments White Paper No.2, Nov 2007.

---

## 1. 结论先行

用**连续时间戳 + 上位机后处理**测起振时间：DMA 提前 arm，`CTR_START_T` 检出后
两次 AXI 写锚定时间原点，此后每个边沿（或每 `edge_skip+1` 个）产生一条 64 位时间戳，
上位机做滑动窗口最小二乘还原 f(t) 曲线，在曲线上找进入 ±PPM 窗口的时刻。

| 指标 | 值 |
|---|---|
| t=0 不确定度 | 1~3 µs |
| 时间分辨率 | 0.04~2 ms，按窗口跨度选 |
| 频率分辨率 | 0.01~0.2 ppm |
| 首边沿时刻 t_first | 直接给出，3.2 ns 量化 |
| 输出 | 完整 f(t) 曲线 |
| RTL 改动 | **不需要** |

方法的基础是时间戳路径的 TDC：已实测 21.0 ps/抽头、256 抽头，单条时间戳的时间
不确定度 σ_t ≈ 30 ps（由 README 实测的 819 µs / 4096 条 / 0.002 ppm 反推）。
这就是论文里 CNT-91 用来在 50 µs 内给出 1 ppm 的那个"50 ps"插值能力的对应物 ——
没有亚周期插值，ppm 级判据与毫秒级时间分辨率不可能同时成立。

## 2. 与论文的对应关系

| 论文（CNT-90/91） | 本机 |
|---|---|
| FREQ Back-to-Back、零死区连续时间戳 | `ts_engine.v`，gap-free，每边沿一条 64 位时间戳 |
| 50 ps / 100 ps 插值 | CARRY4 TDC，21.0 ps/抽头，256 抽头 |
| 电源上升沿经电容耦合进输入 A，产生 time 0 的第一条时间戳 | 专用 `CTR_START_T` 输入（J14）+ `TS_RST` 归零 coarse |
| 测量时间 (meas time) 决定分辨率 | 滑动窗口跨度 W 决定分辨率 |
| 样本数 × 测量时间 = 总捕获时长 | 4096 × (edge_skip+1) / f_x |
| TimeView 里读游标、导出 Excel 算频率 | 上位机滑动窗口最小二乘 |
| 判据：偏差落入 1~几 ppm | 上位机设定的 `PPM` 窗口 |

论文的 setup 用一个电容+二极管把电源上升沿耦合到测量输入，让它变成"第一个时间戳"。
本机有独立的 `CTR_START_T` 触发脚，比这个更干净 —— 代价是它进的是 AXI 寄存器
而不是时间戳流，所以零点要靠 `TS_RST` 来对齐（见第 4 节）。

## 3. 测量模型与定义

### 3.1 时间原点

t = 0 定义为 **DUT 上电时刻**，由 `CTR_START_T` 上升沿标记。

固件把 `TS_RST` 的释放时刻对齐到 t = 0，此后所有时间戳的 coarse 字段即为
「距上电的时间 / 3.2 ns」。coarse 32 位，回绕周期 2³² × 3.2 ns = **13.74 s**。

### 3.2 两个特征时刻

论文里这两个是分开的，工程上也必须分开报告：

- **t_first —— 首个可检出边沿时刻**
  即第一条时间戳的 coarse × 3.2 ns。物理含义是振荡幅度爬升到前端比较器门限的时刻。
  论文图里读到的 "approx 1.3 ms" 就是这个量。
  它依赖前端门限，跨设备可比性差，但同一台仪器上重复性极好。

- **t_settle —— 频率进入 ±PPM 窗口并保持的时刻**
  即本方案要求的"起振时间"。

### 3.3 判据

设标称频率 f_nom（由 `CONF:FREQ` 给定），容差 δ ppm（由 `PPM` 给定），
f(t) 为滑动窗口回归得到的瞬时频率：

```
t_settle = min { t : |f(τ) − f_nom| / f_nom × 10⁶ ≤ δ ，对所有 τ ∈ [t, t + T_hold] }
```

`T_hold` 是保持时间，建议取 3 个窗口跨度。**必须加保持条件** —— 起振过程中频率是
振荡收敛的，单点穿越窗口就判定会显著低估起振时间。

f(t) 的时间坐标取窗口的**中点**，对应论文第 4 页那句"如果窗口内频率变化可近似为
线性，频率值应参考到 timestamp + 50% 测量时间"。

### 3.4 基准的选择

默认以 f_nom 为基准，与论文一致。后处理时应**同时**输出以采集末段稳态频率
f_∞ 为基准的结果：前者是绝对准确度判据（含 DUT 本身的频差），后者是收敛速度判据。
两者对同一批器件常给出很不同的排序，报告里要注明用的是哪个。

## 4. 采集时序设计（方案核心）

### 4.1 现有流程为什么不能直接用

`CaptureTimestamps()`（[freq_counter_core.c:443](../top_cymometer.sdk/FreqCounterOS/src/freq_counter_core/freq_counter_core.c:443)）的顺序是：

```
TS_RST 脉冲  →  写 EDGE_SKIP / PKT_LEN  →  poison 4096 条 + cache flush
             →  XAxiDma_SimpleTransfer  →  TS_EN = 1
```

coarse 的零点在第一步，而引擎真正开始捕获在最后一步，中间隔着 poison 缓冲区
（4096 次 64 位写 + `Xil_DCacheFlushRange`）和 DMA 配置，几十到几百微秒且不确定。
这段时间会被整体计入起振时间。

### 4.2 重排后的流程

关键前提已核实：`stream_en` 直接接 `ts_en`（[counter_core.v:165](../ip_repo/Counter_Core/Counter_Core_1.0/src/counter_core.v:165)），
`TS_EN = 0` 时 `pop_cnt` 保持复位、引擎不向下游吐任何数据。因此 **DMA 可以提前
arm 好空等**，不违反「引擎只能在 DMA 已 armed 的前提下开启」这条规矩（README 已知问题 2）。

```
阶段 A  准备（可以慢，发生在触发之前）
  A1  清 DMA 的 IOC/Err latched 状态
  A2  写 EDGE_SKIP、TS_PKT_LEN = 条目数
  A3  poison 缓冲区 + Xil_DCacheFlushRange
  A4  XAxiDma_SimpleTransfer(...)      ← DMA armed，等 TVALID
      此时 TS_EN = 0，引擎不吐数据，DMA 干等

阶段 B  等触发（忙轮询，不 sleep）
  B1  while (ReadSTARTT() != 1) { 超时检查 }
      单次 AXI-Lite 读约 0.3~1 µs，即检出延迟 ≤ 1 µs

阶段 C  启动（检出后立即执行，两次 AXI 写）
  C1  core_wr(CTRL, TS_RST)            ← coarse 归零，FIFO 清空
  C2  core_wr(CTRL, TS_EN)             ← 释放复位并使能，t = 0 锚定在此
      注意：不要在 C1/C2 之间插 usleep(10)。TS_RST 只需要几个 clk_fs
      周期，而两次 AXI 写本身的间隔已经远超这个数

阶段 D  等采满
  D1  轮询 DMA 的 IOC 位，usleep(100)
  D2  超时按最坏起振时间设定，见 5.4

阶段 E  收尾
  E1  core_wr(CTRL, 0) 停引擎
  E2  清 latched 状态、必要时 XAxiDma_Reset
  E3  Xil_DCacheInvalidateRange，读 LOST_COUNT
```

阶段 C 的两次 AXI 写之间约 0.3~1 µs，加上 B1 的检出延迟，**t = 0 的总不确定度
约 1~3 µs**，且是可标定的系统性偏置（用示波器同时看 STARTT 与某个 GPIO 翻转即可标定一次）。

### 4.3 为什么等待期不浪费缓冲

DUT 未上电时 `clk_fx` 没有任何跳变，`edge_raw` 恒 0，引擎一条时间戳都不产生。
所以 4096 条全部落在起振之后。这是时间戳法相对固定闸门法的结构性优势：
**死区自动被跳过**，不需要为"可能等很久"预留任何采样预算。

推论：第一条时间戳的 coarse 值本身就是 t_first，不需要额外机制去测它。

### 4.4 TS_RST 与下游 FIFO

`TS_RST` 够不到 `axis_data_fifo_0`（README 已知问题 2，硬件根治的
`stream_aresetn` 连线尚未在 BD 中完成）。本流程天然规避：整个过程中
`TS_EN` 只在 C2 拉高一次，且 DMA 已 armed，不存在"引擎开着但没人收"的窗口。
`CaptureTimestamps()` 里那段「陈货 coarse 远大于后续数据则丢弃首条」的软件规避
应当保留 —— 但在本流程下它同时会误伤真正的第一条（t_first）。
**实现时必须把这个规避改成基于 poison 值和 seq 的判断，不能用 coarse 倒流判据。**

## 5. 参数选择

### 5.1 覆盖跨度

```
T_cover = 4096 × (edge_skip + 1) / f_nom        （从首个边沿起算）
edge_skip = ceil( T_cover × f_nom / 4096 ) − 1
```

`edge_skip` 严格按边沿计数分频，硬件保证，所以窗口内的频率
f = (edge_skip+1) × ΔN / Δt 中的边沿数是确定的。

### 5.2 频率分辨率

滑动窗口取 N 条、跨度 W 的最小二乘拟合：

```
δ [ppm] ≈ σ_t × √12 / (√N × W) × 10⁶ ,  σ_t ≈ 30 ps
        ≈ 1.04×10⁻¹⁰ / (√N × W[s]) × 10⁶
```

N = 64 时简化为 **δ ≈ 1.3×10⁻⁵ / W[s] ppm**。

窗口跨度 W 同时就是本方案的**时间分辨率**（f(t) 的时间平滑宽度）。
分辨率与时间分辨率的乘积是常数 —— 这与论文第 4 页
"Measuring time determines resolution" 说的是同一件事，只是常数从 50 ps 变成 30 ps。

### 5.3 推荐工作点

窗口固定 64 条，条目数固定 4096：

| f_nom | 器件类型 | 目标覆盖 | edge_skip | 实际跨度 | 窗口 W | δ | 备注 |
|---|---|---|---|---|---|---|---|
| 32.768 kHz | 音叉晶振 | 125 ms | 0 | 125 ms | 1.95 ms | 0.007 ppm | 起振后细看 |
| 32.768 kHz | 音叉晶振 | 1 s | 7 | 1.00 s | 15.6 ms | 0.0008 ppm | 全过程 |
| 1 MHz | XO | 41 ms | 9 | 41 ms | 0.64 ms | 0.020 ppm | |
| 10 MHz | XO / TCXO | 10 ms | 24 | 10.2 ms | 160 µs | 0.081 ppm | 典型档 |
| 10 MHz | TCXO 热稳定 | 100 ms | 249 | 102 ms | 1.6 ms | 0.008 ppm | |
| 20 MHz | XO | 10 ms | 48 | 10.0 ms | 157 µs | 0.083 ppm | |
| 50 MHz | XO | 10 ms | 121 | 10.0 ms | 156 µs | 0.083 ppm | |
| 100 MHz | XO / VCXO | 10 ms | 243 | 10.0 ms | 156 µs | 0.083 ppm | |
| 100 MHz | 热稳定 | 100 ms | 2440 | 100 ms | 1.56 ms | 0.008 ppm | |

三点说明：

- 所有工作点的 `edge_skip` 都远大于 0，**不存在 README 已知问题 2.2 的带宽压力**
  （那条针对 99 MHz / `edge_skip = 0` 的 792 MB/s）。实际数据率均低于 1 MB/s。
- 需要更细的时间分辨率就减小窗口 N：N = 16 时 δ 变差 2 倍，W 缩到 1/4。
  10 MHz 典型档下 N = 16 → W = 40 µs、δ = 0.33 ppm，对 ppm 级判据仍有余量。
- 超过 140.625 MHz（clk_fs 奈奎斯特的 90%）的 DUT 无法逐边沿时间戳，本方案不覆盖。

### 5.4 DMA 超时

```
timeout_ms = t_first_max + T_cover × 1.5 + 50
```

`t_first_max` 按器件类型取：XO/TCXO 50 ms，音叉晶振 5 s，OCXO 按数据手册。
上限受 coarse 回绕限制，**t_first 不得超过 13.7 s**，否则 coarse 绕回、时间轴错乱。
音叉晶振若可能超过这个数，需要在阶段 B 与 C 之间插入分段策略，本方案不覆盖。

### 5.5 条目数上限与 DMA 模式

5.3 的表基于现有的 `TS_BUF_ENTRIES = 4096`。这个数字是软件选的
（注释称"matching the IP's internal FIFO depth"），**不是 DMA 的限制**。
FIFO 深度与单次传输长度本来就不需要相等：DMA armed 后持续搬运，只要吸收速率
高于产生速率 FIFO 就不会满，而本方案所有工作点的数据率都低于 1 MB/s。

实际上限：

| 约束 | 上限 | 出处 |
|---|---|---|
| DMA buffer length register | 131 071 条（1 MB) | `c_sg_length_width = 20` |
| `TS_PKT_LEN` / `pkt_limit` | **65 535 条** | `ts_engine.v` 的 `pkt_limit[15:0]` |

即 simple mode 单次可采 **65 535 条**，是现有配置的 16 倍，且是纯软件改动
（加大静态缓冲 + 传更大的 `entries` / `pkt_len`），不需要动 BD 或重新综合。

收益（10 MHz、覆盖 10 ms、`edge_skip = 1`、实际跨度 13.1 ms）：

| 取舍 | 4096 条 | 65 536 条 |
|---|---|---|
| 固定时间分辨率 160 µs | δ = 0.081 ppm | δ = **0.023 ppm** |
| 固定 δ = 0.081 ppm | W = 160 µs | W = **69 µs** |

条目数 ×16 换来 δ 改善约 4 倍（√N 规律）或时间分辨率改善约 2.3 倍，两者可按
5.2 的公式在预算内自由分配。代价是 512 KB 静态缓冲（需确认 linker script 的
`.bss` 容纳）和相应加大的 DMA 超时。

**Scatter-Gather 对本方案没有帮助**，理由三条：

1. 本方案只有一次传输。README 已知问题 4 描述的"两次传输之间 20~100 µs 空档"
   是 SG 要解决的问题，而触发式单次采集不存在第二次传输。
2. 等待期不消耗缓冲（4.3），"可能等很久"对 DMA 没有压力。
3. 样本量不足时先加大 simple mode 的单次长度，65 535 条已覆盖本方案全部工作点。

且 `c_include_sg = 0`，启用 SG 需要在 BD 中打开 Scatter Gather Engine、
接出 M_AXI_SG 主口、重新综合实现并重建 BSP，软件也要改用 `XAxiDma_BdRing*` API ——
这会与已知问题 1（256 抽头 TDC 未上板）和已知问题 3（缺时序约束）纠缠在同一轮迭代里。

SG 真正必要的场景是**总过程超出 65 535 条的覆盖能力且要求全程 gap-free**，
典型是 OCXO 从上电到 ±1 ppb 的数分钟热稳定过程（需千万条级样本，必须 cyclic
描述符环边采边回传）。注意即便上了 SG，`pkt_limit` 仍是 16 位，真正的无限流
需要设 `pkt_limit = 0`（无 TLAST）并由描述符环界定，S2MM 在该配置下的行为
需另行验证。

## 6. 需要新增的固件接口

以下均为**待实现项**，本文档不改动任何代码。

### 6.1 采集函数

```c
/* Startup capture: arms the DMA first, then waits for the external trigger,
   so the coarse zero point and the capture start are two AXI writes apart
   instead of a poison pass apart. */
int StartupCapture(u64 *buf, int entries, u32 edge_skip, u32 trig_timeout_ms,
                   u32 capture_timeout_ms);
```

与 `CaptureTimestamps()` 的差别仅在阶段顺序（4.2）与陈货判据（4.4）。
建议新增函数而不是改 `CaptureTimestamps()` —— 后者被 `ReadFr_TimestampMode()`
和 `TimestampTest()` 依赖，其现有顺序对普通测频是正确的。

### 6.2 SCPI 命令

| 命令 | 参数 | 响应 | 说明 |
|---|---|---|---|
| `STARTUP:SKIP <n>` | int | 无 | 设 `edge_skip`；不设则由 `CONF:FREQ` 按 5.3 自动推算 |
| `STARTUP:HOLD <n>` | int | 无 | 保持窗口数，默认 3 |
| `STARTUP:INIT` | — | 无 | 执行 4.2 全流程，阻塞 |
| `STARTUP:STAT?` | — | `<code>,<n_entries>,<lost>` | 0 = 成功，−1 触发超时，−2 采集超时，−3 溢出 |
| `STARTUP:FIRST?` | — | `%.6f` ms | t_first |
| `STARTUP:TIME?` | — | `%.6f` ms | t_settle，未达标返回 `-1.000000` |
| `STARTUP:DATA? <off>,<cnt>` | int,int | CSV 行 | 导出 f(t) 曲线点，用于画论文那种图 |

要点：

- `STARTUP:INIT` 必须有响应（哪怕只是 `0\n`）。本设备已有多条命令不返回任何数据
  （协议文档 1.5 节），上位机普遍按"每条命令必有响应"实现，新命令不要延续该缺陷。
- `STARTUP:DATA?` 分块导出。`SCPI_RESP_MAX` 是 384 字节，原始时间戳 4096×8 B = 32 KB
  一次发不下。**建议导出的是 f(t) 曲线点而不是原始时间戳**：4096 条 / 64 窗口步进
  = 64 个点，每点 `t_ms,f_hz` 约 30 字节，总共不到 2 KB，分 8 块即可。
  需要原始数据做深入分析时另开一条命令走批量传输。
- 判据计算放在固件还是上位机？**建议固件算 t_settle、同时提供曲线导出**。
  固件算能保证产线单次往返出结果；曲线用于异常品复盘和论文作图。

### 6.3 触发的电平语义

`ReadSTARTT()` 读的是 `Counter_Sig` REG2 bit0 的**电平**，不是边沿。因此：

- 必须先发 `STARTUP:INIT`，再拉高 `CTR_START_T`。顺序反了会立即"检出"，
  t = 0 变成命令到达时刻。
- 一次测量结束后必须把 `CTR_START_T` 拉低，否则下一次 `STARTUP:INIT` 立即通过。
- 触发信号需保持到被检出，忙轮询下 ≥ 10 µs 即足够，实务上建议保持到测量结束。

## 7. 上位机后处理

```python
COARSE_PS = 3200.0          # clk_fs period, ps  (312.5 MHz nominal)
TDC_TAPS  = 256

def ts_to_seconds(word, f_s):
    coarse = (word >> 32) & 0xFFFFFFFF
    tdc    = (word >> 24) & 0xFF
    tdc_ok = (word >> 22) & 1
    # tdc counts up along the delay chain; the fine part advances the edge
    # within the coarse period. Discard the fine part when tdc_ok is 0.
    frac = (tdc / TDC_TAPS) if tdc_ok else 0.0
    return (coarse + frac) / f_s

def sliding_freq(ts, edge_skip, win=64, step=8):
    """Least squares fit over a sliding window -> (t_mid, f) points."""
    out = []
    k = edge_skip + 1
    for i in range(0, len(ts) - win, step):
        seg = ts[i:i+win]
        n   = np.arange(win) * k              # edge index within the window
        # slope of t vs edge index = period
        p   = np.polyfit(n, seg, 1)
        out.append((0.5 * (seg[0] + seg[-1]), 1.0 / p[0]))
    return out

def settle_time(points, f_nom, ppm, hold):
    """First point that enters the window and stays for `hold` points."""
    lim = f_nom * ppm * 1e-6
    for i in range(len(points) - hold):
        if all(abs(points[j][1] - f_nom) <= lim for j in range(i, i + hold + 1)):
            return points[i][0]
    return None
```

三处必须注意：

1. **f_s 用校准值**。`SIG:STATUS0?` 应为 1，运算基准取 SD 卡 `FREQ.TXT`。
   基准本身的偏差直接进入 ppm 判据 —— 判据是 1 ppm 而基准未校到 0.1 ppm 的话，
   测的是基准不是 DUT。
2. **`ovf` 字段不可信**（README 已知问题 2.1），判连续性要用 `seq` 与 coarse 增量，
   并检查 `STARTUP:STAT?` 返回的 `lost`。
3. **起振初期可能有噪声毛刺过门限**。回归残差可作为信号质量指标：
   残差 RMS 显著大于 σ_t 的窗口应标记为"尚未形成稳定振荡"，不参与判据。
   这一段正是 t_first 与 t_settle 之间的物理内容。

---

## 8. 不确定度预算

以 10 MHz 典型档（`edge_skip = 24`，窗口 64 条，W = 160 µs）为例：

| 分量 | 量值 | 类型 | 处置 |
|---|---|---|---|
| t = 0 锚定（B1 检出 + C1→C2 写间隔） | 1~3 µs | 系统 + 随机 | 示波器标定一次，扣除系统偏置 |
| coarse 量化 | 3.2 ns | 随机 | 可忽略 |
| TDC 单条抖动 σ_t | 30 ps | 随机 | 已含在 δ 中 |
| 窗口回归频率分辨率 | 0.081 ppm | 随机 | 减小 δ 需加大 W |
| 时间分辨率（窗口宽度） | 160 µs | 系统 | 判据取窗口中点，偏置已消 |
| 基准频率 f_s 不确定度 | 取决于 `FREQ.TXT` 校准 | 系统 | 直接进入 ppm 判据，必须先校准 |
| 前端门限（影响 t_first） | 器件相关 | 系统 | 同机可比，跨机需注明 |

合成后，t_settle 的不确定度由**时间分辨率 160 µs**主导，t_first 的不确定度由
**t=0 锚定 ~3 µs**主导。对 ms 级起振过程分别是 1.6% 和 0.1%。

按 5.5 加大单次条目数可进一步压低这两项中的第一项。

## 9. 测试流程

### 9.1 夹具要求

- DUT 输出接 `clk_fx_p/n`（B19，LVDS_25），经现有前端。
  **需要先在 C1804 REV04 原理图上确认输入通道的比较门限与最小可检出幅度** ——
  它直接决定 t_first 的物理含义。本文档未核对该细节。
- `CTR_START_T`（J14，LVCMOS25）与 DUT 供电开关同源驱动，上升沿 < 100 ns。
  两路信号的相对延迟需一次性标定并从结果中扣除。
- 供电上升沿的斜率、负载电容、温度都显著影响起振时间，同一批测试必须固定。

### 9.2 单次测量命令序列

```
*IDN?
SIG:STATUS0?            → 应为 1（使用 SD 卡校准的基准频率）
CONF:FREQ 10000000
PPM 1
STARTUP:SKIP 24
STARTUP:HOLD 3
STARTUP:INIT            → 阻塞；随后由夹具给 DUT 上电并拉高 STARTT
STARTUP:STAT?           → 0,4096,0
STARTUP:FIRST?          → 1.284631
STARTUP:TIME?           → 3.472000
STARTUP:DATA? 0,16      → 曲线点，按需分块取完
```

然后拉低 `CTR_START_T`、DUT 断电、等待放电（建议 ≥ 30 s 或至电源跌至 50 mV 以下），
再进行下一次。

只维持单一 TCP 连接、串行下发（协议文档第 6 节）。

### 9.3 批量与统计

- 每个样品重复 10 次，报告 t_first 与 t_settle 的**中位数与极差**，不用均值 ——
  起振时间分布常有长尾。
- 每批保留至少 3 条完整 f(t) 曲线用于复盘。
- 异常判定：`STARTUP:STAT?` 非 0、`lost` 非 0、或回归残差 RMS 超阈值的样本单独归类，
  不混入统计。

### 9.4 报告字段

```
样品编号 / 标称频率 / 器件类型 / 供电电压与上升时间 / 环境温度
edge_skip / 窗口条数 / PPM 判据 / 判据基准（f_nom 或 f_∞）
t_first  中位数 ± 极差   (n = 10)
t_settle 中位数 ± 极差   (n = 10)
f_∞（采集末段稳态频率）与相对 f_nom 的偏差
```

## 10. 与现有已知问题的交互

| README 已知问题 | 对本方案的影响 | 处置 |
|---|---|---|
| 2 下游 `axis_data_fifo` 不受 `TS_RST` 复位 | 无（本流程先 arm 后使能） | 陈货规避改用 poison + seq 判据，见 4.4 |
| 2.0 启动首拍竞态 | 可能使头两条间隔异常 | 已在 RTL 修复但未上板验证；后处理应对首条单独校验 |
| 2.1 `ovf_mark` 恒 0 | `ovf` 不可信 | 用 `seq` 连续性 + `LOST_COUNT` 判断 |
| 2.2 带宽上限约 50 MHz | 不触发（所有工作点 `edge_skip` ≫ 0） | — |
| 3 `clk_fs` / `clk_fx` 缺时序约束 | TDC 与引擎路径未被时序分析覆盖 | 上板验证前应补约束并重跑时序 |
| 4 DMA 仍是 simple mode | 无影响：本方案只有一次传输，不存在传输间空档 | 不需要 SG；样本量不足时加大单次条目数至 65 535，见 5.5 |
| 1 TDC 256 抽头未上板验证 | δ 的推算基于 21.0 ps/抽头 | **必须先完成 256 抽头的上板验证与码密度标定**，否则 δ 只是估算值 |

256 抽头版本尚未综合上板。上板并重做码密度标定后，δ 的数值需要按实测重算，
但方案结构不变。

## 11. 未采用方案的记录

**改 RTL 把 STARTT 打进时间戳流** —— 可以把 t = 0 的不确定度从 ~3 µs 降到 3.2 ns
（例如新增一个只读寄存器锁存 STARTT 上升沿时刻的 `free_run_cnt`）。
本方案不采用：ms 级起振过程下 3 µs 已是 0.1%，不值得为此引入一轮
打包 IP → Upgrade BD → 重新综合实现的迭代。若后续要测亚毫秒级起振（如 MEMS 振荡器
或 LC 振荡器），再考虑这一改动。
